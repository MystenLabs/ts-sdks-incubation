## Known weaknesses

1. **CLI Phase B/C never landed.** Plan promised
   `wipe`→`reset`, splits of `fork.ts` (1,048 LoC) and `doctor.ts`
   (897 LoC), `manifest`/`status` fold. Phase A wired envelope/sysexits
   alongside legacy paths instead of replacing them.

2. **Exit codes are documented but un-wired.** `cli/exit-codes.ts`
   defines 13 codes; only 7 have callsites; `cli/main.ts` teardown
   collapses every non-success to `1`. The envelope shape's
   `error.exitCode` is correct in JSON output but the process exit
   code doesn't match.

3. **Heavy comment overhead on substrate files.** CLAUDE.md prescribes
   "default to no comments"; the substrate carries 30–60 line block
   comments explaining invariants on most callsites. Attempted to
   sweep this and pulled the agent before it finished. Probable
   −500 to −1,000 LoC if done carefully.

4. **`_prune-stack.ts` (438 LoC) is engine-orchestration in `cli/`** per
   audit E58. Now that `removeDockerByLabel` lives in `engine/`, moving
   the rest is the natural next step.

5. **stale `[pinned.*]` writes to `Move.lock`** from test runs are
   reverted, but their presence indicates the build container isn't
   fully hermetic on `Move.lock` mutations.

6. **`_internal` re-export blocks** in `cli/commands/fork.ts` and
   `engine/sui-fork/control.ts` exist purely so tests can import
   non-public helpers. The fix is teach tests to import from canonical
   sources — pattern flagged but not removed.

7. **CC-1 envelope helper** consolidated 15 callsites; the other 32
   "candidates" preserved different shapes (cause-passing, raw Errors,
   non-JSON-aware paths). The audit overcounted by ~3x — a recurring
   pattern across this session.

## What a rewrite should keep

If you tear down and rewrite, these are the structural wins worth
preserving (even if reimplemented):

1. **`ChainProbe` substrate** — Schema-validated SDK reads. Killed B1
   (response-shape drift) and B7 (gRPC long-form objectType) bug
   classes. Roughly 60 LoC of substrate, eliminates ~30 LoC of casts
   per service.

2. **`onChainArtifact` cache + verify + register contract** — the
   `display: (s: T) => …` anchor for inference, the
   `register` running on hit + miss, and the lean cached payload vs
   rich consumer-facing tag pattern. RS1-3 restart-survival invariants
   (canonicalize build-output for inputs, probe stable identifiers,
   `runOk` for exit codes) are real and earned by debugging.

3. **`ensureContainer` adopt/start/recreate primitive** — the lifecycle
   state machine deduplicated two engine paths.

4. **`buildCacheKey({namespace, chainId, inputsHash})` flat shape** —
   the per-primitive `name` segment lives in the cached value, not the
   key. Phase B publishMove migration enforced this and the test code
   eventually caught up.

5. **`failWithEnvelope` helper + `--json` envelope shape** — the JSON
   envelope is good. Keep it.

6. **`@clack/prompts` confirmation + `--no-input` global** — Phase A's
   prompt substrate works.

## What a rewrite should throw away

1. **The vN/version-segment fossils** — already swept, but be vigilant.

2. **The "Phase A wired alongside legacy" pattern in `cli/`** — the
   per-command files carry both the legacy `failAlreadyReported(...)`
   path AND the new envelope path. Pick one and delete the other.

3. **The `_internal` test-export blocks**.

4. **`emitSuccess` / `EX_OK` and the half-wired exit codes** — either
   wire them at process exit (`main.ts:tapCause`) or delete them.

5. **`schema-emit.ts`** — 164 LoC, unclear who reads
   `devstack --schema --json`. Keep iff there's a real consumer; else
   delete.

6. **Block-comment substrate documentation** — substrate file should
   hold one canonical doc; per-callsite explanations are noise.
