---
title: codegen
description: Typed Move bindings via @mysten/codegen with MVR-shaped placeholders that the SDK resolves at tx-build time.
---

`codegen({ output?, mvrName? })` contributes one Emit action that runs
`generateFromPackageSummary` from `@mysten/codegen` against every package registered in
`registry.packages.list()` whose `path` is set.

| Option    | Default                                | Notes                                                                                  |
| --------- | -------------------------------------- | -------------------------------------------------------------------------------------- |
| `output`  | `'src/generated/sui'`                  | Output directory relative to `appDir`.                                                 |
| `mvrName` | `(n) => '@local/' + n.replace(/_/g, '-')` | Maps a registry package name to the MVR-shape placeholder embedded in emitted builders. |

The Emit declares `dependsOnKind: ['packages']`, so it re-fires whenever a Publish action registers
a fresh package — no explicit `needs:` edges from your plugins.

## What it generates

For each `<package>`, codegen writes typed builders under `<output>/<package>/<module>.ts`. Each
Move function becomes a builder:

```ts
// In your generated bindings:
export function createLobby(options: CreateLobbyOptions = {}) {
	const packageAddress = options.package ?? '@local/connect-four';
	return (tx: Transaction) =>
		tx.moveCall({
			/* ... */
		});
}
```

The placeholder `'@local/<kebab-name>'` is a valid MVR name. The SDK's
`namedPackagesPlugin` (auto-installed on every `Transaction#build`) resolves it to the live
`packageId` at transaction-build time, using the `mvr.overrides.packages` config wired by
[`localnetDappKitConfig(manifest)`](/devstack/adapters/react). App code calls the builder
directly:

```ts
import * as connectFour from './generated/sui/connect_four/game';

const tx = new Transaction();
tx.add(connectFour.joinLobby({ arguments: [lobbyId] }));
await dAppKit.signAndExecuteTransaction({ transaction: tx });
```

No `bindPackage`, no per-call `package: deployment.connectFourPackageId` boilerplate. The same
component code works on testnet/mainnet — only `dapp-kit.ts` differs (drops the
`localnetDappKitConfig` spread; supplies its own RPC + a different `mvr.overrides` map or real
on-chain MVR).

## Custom mvrName

Apps that want a different MVR org override the mapper. Pass the same function to `codegen`
**and** to `localnetDappKitConfig` so the codegen output and the override key agree:

```ts
const mvrName = (n: string) => `@arena/${n.replace(/_/g, '-')}`;

// devstack.config.ts
plugins: [/* ... */ codegen({ mvrName }), /* ... */];

// dapp-kit.ts
const dAppKit = createDAppKit({
	...localnetDappKitConfig(manifest, { mvrName }),
	walletInitializers: [...],
});
```

The mapper output must be a valid MVR name (kebab-case `<app>` after a SuiNS-shaped `<org>`).
Snake_case in the emitted placeholder fails `@mysten/sui`'s validation at SuiClient
construction.

## Pathless packages

Imported packages whose source lives inside a docker image (deepbook, seal) have `path: undefined`
on their registry entry. Codegen silently skips them. If you want generated bindings for an imported
package, copy its source out of the image to a host path — see the imports plugin's escape hatches.
