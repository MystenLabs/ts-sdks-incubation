## Prerequisites

- **Node.js 24+** and **pnpm 10+**. Node 24 strips TypeScript annotations natively, so
  `devstack.config.ts` loads via plain `import()` — no tsx, ts-node, or pre-build step.
- **Docker Desktop** (or Colima) running. devstack ships sui-localnet, walrus, and seal as
  containers.
- **Apple Silicon or Linux x86_64.** Native execution only — no Rosetta or qemu.
- **Sui CLI** (>= 1.51.1) on PATH. Required for codegen and live-network publishes; localnet
  publishes use the in-container CLI.

## Install

```sh
pnpm add -D @mysten-incubation/devstack
```

## Configure

Create a `devstack.config.ts` in your app root:

```ts
import { dirname, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';

import {
	codegen,
	defineDevstackConfig,
	frontend,
	publishMove,
	sui,
} from '@mysten-incubation/devstack';

const HERE = dirname(fileURLToPath(import.meta.url));

export default defineDevstackConfig({
	app: 'my-app',
	accounts: {
		publisher: {},
		alice: {},
		bob: {},
	},
	plugins: [sui(), codegen(), frontend({ port: 5173 })],
	setup: [
		publishMove({
			name: 'my_package',
			needs: ['sui.accounts'],
			path: resolve(HERE, 'move/my_package'),
		}),
	],
});
```

Account names declared at the top level are funded on localnet via the faucet. Empty objects (`{}`)
get a per-stack generated keypair on disk; live-network deployments override per network — see the
[accounts page](/devstack/concepts/accounts).

The [`setup:` field](/devstack/concepts/setup) is where app-level state lives: publish Move packages,
mint fixture coins, create initial shared objects. Each item is an action with explicit `needs` for
ordering and `getStatus` for idempotence — same primitives the framework's own plugins use, just
declared inline. Use `publishMove()` and `runTransaction()` for the common cases; drop into
`seed()` / `definePublishAction()` directly when you need a custom probe.

The [`frontend()` plugin](/devstack/plugins/frontend) brings the dev server up alongside the rest of the
stack so a single `pnpm dev` script handles localnet + publishes + codegen + the UI dev server in
one combined process.

## Bring it up

Wire your `package.json` scripts to the `devstack` binary:

```jsonc
{
	"scripts": {
		"dev": "devstack up",
		"apply": "devstack apply",
		"codegen": "devstack codegen",
		"deploy": "devstack deploy",
		"stack": "devstack stack",
	},
}
```

Then:

```sh
pnpm dev                        # one combined process: stack + dev server
```

`devstack up` is the long-running supervisor — it brings up sui-localnet, funds accounts,
publishes Move packages, regenerates codegen bindings, and starts the Vite dev server in one log
stream. Watches Move sources and re-reconciles on change. Cold cycles are dominated by
container startup; warm cycles short-circuit through `getStatus` and complete much faster (the
hot path is service-liveness probes plus a registry-snapshot read).

For a single bring-up + exit (CI / e2e setup) — same actions, no supervisor, no source-watching:

```sh
pnpm exec devstack apply
```

## What happened

1. The `sui` plugin built `dev-examples/sui-localnet:<version>-r7`, started the container, and
   provisioned the keypairs you declared in `accounts:`. The chain ledger lives in the container's
   writable layer — `docker stop` + `docker start` resumes it; `docker rm` destroys it.
2. The port allocator picked a free TCP port for sui's RPC + faucet (preferring `9000`/`9123` if
   they were free), persisted it to `<stackDir>/ports.json`, and registered the resolved URL in
   the manifest. Sibling stacks of the same app see those claims and avoid them automatically.
3. Each `publishMove()` (or `definePublishAction()`) action under `setup:` ran `sui move build`
   inside the container + a publish tx and recorded the package id in the manifest.
4. `codegen` regenerated typed bindings under `src/generated/sui/<package>/`.
5. The manifest was written to `<appDir>/.devstack/stacks/main/manifest.json`. Your Vite-built
   frontend reads it via the `virtual:devstack-manifest` module.

## Snapshots

After a stack is healthy, capture it for fast restore:

```sh
pnpm exec devstack snapshot save baseline
pnpm exec devstack stack drop main --yes --force   # nuke for the demo
pnpm exec devstack snapshot restore baseline       # ~1 s
pnpm exec devstack apply                            # ~5 s — every action skips
```

`snapshot save` `docker commit`s every stateful container into a seed image and copies
`<stackDir>` into `<appDir>/.devstack/snapshots/<id>/`. Restore re-tags the seed images back to
their original names so the next `devstack up` starts containers with the seeded state already in
place. CI uses `snapshot save baseline --push ghcr.io/myorg/...` to ship snapshots through GHCR.
