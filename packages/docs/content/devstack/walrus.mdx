title: Walrus
description: Local Walrus clusters, known deployments, and WAL funding.

Store and retrieve blobs from a Walrus cluster running on your local network. Add `walrus()` to your
stack to start the cluster, then build a `WalrusClient` from the ids it resolves at boot.

Local mode starts the cluster. Use `walCoin(localWalrus)` with account funding when an account needs
WAL.

```ts title="devstack.config.ts"
import { account, defineDevstack, sui, walCoin, walrus } from '@mysten-incubation/devstack';

const localnet = sui();
const localWalrus = walrus({
	local: {
		nodeCount: 1,
		shards: 4,
	},
});
const wal = walCoin(localWalrus);

const alice = account('alice', {
	funding: [
		{ coin: 'sui', amount: 1_000_000_000n },
		{ coin: wal, amount: 500_000_000n },
	],
});

export default defineDevstack({ members: [localnet, localWalrus, alice] });
```

Known mode points at an existing deployment and requires explicit on-chain ids plus an explicit node
list. Fork stacks can use `walrusFor(forkNetwork).known(...)` for upstream deployments; local Walrus
clusters run only on local networks.

`walCoin(walrusMember)` returns the WAL funding coin for that Walrus member. Pass it to account
funding like any other coin ref to give an account WAL.

## Connect the SDK

The config above runs the cluster; the [generated bindings](/devstack/codegen) carry its resolved
ids into your app. Walrus is a per-network service: `walrus.forNetwork(network)` returns the config
for the network your wallet is connected to, so a runtime `switchNetwork` flips the cluster ids in
lockstep. Build a `WalrusClient` from it:

```ts title="src/lib/walrus.ts"
import { useCurrentNetwork } from '@mysten/dapp-kit-react';
import { WalrusClient } from '@mysten/walrus';
import walrusWasmUrl from '@mysten/walrus-wasm/web/walrus_wasm_bg.wasm?url';

import { walrus } from '@generated/walrus.js';

const network = useCurrentNetwork();
const w = walrus.forNetwork(network);

const client = new WalrusClient({
	suiClient,
	packageConfig: w.packageConfig,
	// Local clusters serve plain HTTP behind the devstack proxy; live
	// networks serve HTTPS.
	storageNodeUrlScheme: w.mode === 'local' ? 'http' : 'https',
	wasmUrl: walrusWasmUrl,
});
```

`w.packageConfig` already holds `systemObjectId`, `stakingPoolId`, and `exchangeIds` resolved at
boot — pass it straight through. Keying `storageNodeUrlScheme` off `w.mode` lets the same code reach
a local cluster over HTTP and a known deployment over HTTPS as the connected network changes. See
[`examples/private-content`](https://github.com/MystenLabs/ts-sdks-incubation/tree/main/examples/private-content/src/lib/walrus.ts)
for the full client with blob write/read.
