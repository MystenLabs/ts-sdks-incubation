`Codegen({ output?, packages?, emitters? })` runs a list of **emitters** against a resolved package
set + the live registries (accounts, services, coins, extras). Every option has a sensible default —
calling `Codegen()` with no arguments uses the canonical output path, no explicit package list
(defaults to `[]`; auto-fill from `Package(...)` in the stack is on the roadmap), and all three
built-in emitters.

This page is the reference. For the task-shaped intro see the
[codegen feature page](../features/codegen).

## Output convention

**Default: `./src/generated/`** — exported as `DEFAULT_CODEGEN_OUTPUT` from the main barrel for
tooling that needs to mirror the default (linters, build scripts, monorepo config). The path is
resolved against `process.cwd()` at codegen time.

The three built-in emitters write to:

```
./src/generated/
  bindings/<package-name>/...   ← BindingsEmitter
  accounts.ts                   ← StackHandleEmitter
  services.ts                   ← StackHandleEmitter
  extras.ts                     ← StackHandleEmitter
  captured.ts                   ← StackHandleEmitter
  packages.ts                   ← StackHandleEmitter
  dapp-kit-config.ts            ← DappKitConfigEmitter
```

App code imports them directly:

```ts
import { Lobby } from './generated/bindings/connect_four/game.js';
import { accounts } from './generated/accounts.js';
import { devstackDappKitConfig } from './generated/dapp-kit-config.js';
```

**`.devstack/` is intentionally NOT used.** That dot-dir is reserved for non-importable runtime
state (account keys, wallet tokens, walrus deploy outputs, etc.) and is invisible to TS tooling +
lint configs by convention. See [state and snapshots](../features/state-and-snapshots) for the full
split.

## Zero-config

```ts
import { Codegen } from '@mysten-incubation/devstack';

Codegen({ packages: [hello] });
// equivalent to:
// Codegen({
//   output: './src/generated',
//   packages: [hello],
//   emitters: [BindingsEmitter(), StackHandleEmitter(), DappKitConfigEmitter()],
// })
```

Override individual fields as needed; omit the rest. Re-running with the same inputs is idempotent —
the bindings emitter fingerprints sources and skips the regen when nothing has moved, and the other
emitters skip writes when the rendered bytes match what's on disk.

## Built-in emitters

The three built-in emitters live under `@mysten-incubation/devstack/advanced` (plug-in author
surface). The high-level `Codegen` factory's defaults cover most users.

### `BindingsEmitter`

Move → TypeScript bindings via `@mysten/codegen`.

```ts
import { Codegen } from '@mysten-incubation/devstack';
import { BindingsEmitter, StackHandleEmitter } from '@mysten-incubation/devstack/advanced';

Codegen({
	packages: [hello, world],
	emitters: [BindingsEmitter({ importExtension: '.ts' }), StackHandleEmitter()],
});
```

Output lands at `<output>/bindings/<package-name>/`. Local packages emit fully; `KnownPackage(...)`
entries are silently skipped — bindings need the upstream Move source to feed `sui move summary`.

Atomic dir swap (stage → rename existing aside → rename staging in) means a Vite dev server never
sees a half-written tree mid-cycle.

### `StackHandleEmitter`

Reads the live registries (accounts, services, coins, packages) + the resolved `Extras` service and
emits five files of named, literal-typed handles:

| File          | Shape                                                                            |
| ------------- | -------------------------------------------------------------------------------- |
| `accounts.ts` | `export const accounts = { alice: '0x…', … } as const`                           |
| `services.ts` | `export const services = { sui: { rpc: { url } }, … } as const`                  |
| `extras.ts`   | `export const extras = { …user-defined… } as const`                              |
| `captured.ts` | `export const captured = { mock_usdc: { treasuryCapId: '0x…' }, … } as const`    |
| `packages.ts` | `export const packages = { hello: { id: '0x…', mvr: '@local/hello' } } as const` |

`packages.ts` is the escape hatch for raw ids — prefer MVR-resolved targets
(`tx.moveCall({ target: '@local/hello::hello::mint' })`, which dapp-kit handles via the baked-in
overrides) and the typed bindings under `./bindings/<pkg>/` over raw `packages.<name>.id` lookups.

The emitter has no options today — it reads everything from the registries.

### `DappKitConfigEmitter`

Emits `<output>/dapp-kit-config.ts` — a partial `createDAppKit(...)` config the user's hand-written
`src/dapp-kit.ts` spreads into the kit constructor.

```ts
import { Codegen } from '@mysten-incubation/devstack';
import { DappKitConfigEmitter } from '@mysten-incubation/devstack/advanced';

Codegen({
	packages: [hello, deepbookV3],
	emitters: [DappKitConfigEmitter({ enableBurnerWallet: false })],
});
```

Options:

- **`enableBurnerWallet`** (default `true`) — wire the devstack dev-wallet adapter into
  `walletInitializers`. Set `false` for an emitted config with no wallet pre-wired (your
  `dapp-kit.ts` provides real wallet initializers).

The emitted config exports:

- `devstackDappKitConfig` — `{ defaultNetwork, networks, createClient, walletInitializers }` ready
  to spread into `createDAppKit({ ...devstackDappKitConfig })`.
- `devstackWalletInitializer(opts)` — factory for building a burner-wallet initializer with custom
  options (`{ mountUI: false }`, etc.) when the user wants to override the default.

See [dapp-kit integration](../features/dapp-kit) for the consumer side.

## Writing your own emitter

`defineEmitter({ name, emit })` is the contract:

```ts
import { Effect } from 'effect';
import { defineEmitter, CodegenError } from '@mysten-incubation/devstack/advanced';
import * as fs from 'node:fs/promises';
import * as path from 'node:path';

const VersionListEmitter = defineEmitter({
	name: 'version-list',
	emit: (ctx) =>
		Effect.gen(function* () {
			const lines = ctx.packages.map((p) => `${p.name}: ${p.packageId}`).sort();
			const out = path.join(ctx.outputDir, 'versions.txt');
			yield* Effect.tryPromise({
				try: () => fs.writeFile(out, lines.join('\n') + '\n', 'utf-8'),
				catch: (cause) =>
					new CodegenError({
						emitter: 'version-list',
						phase: 'write',
						message: `failed to write ${out}`,
						cause,
					}),
			});
		}),
});

// Drop into any `Codegen({...})` — the defaults DON'T apply when you
// pass `emitters: [...]` explicitly, so include the built-ins you want:
Codegen({
	packages: [hello],
	emitters: [BindingsEmitter(), StackHandleEmitter(), VersionListEmitter],
});
```

The `CodegenContext` your emit receives carries:

```ts
interface CodegenContext {
	readonly packages: ReadonlyArray<CodegenPackage>;
	readonly outputDir: string;
}

interface CodegenPackage {
	readonly name: string;
	readonly packageId: string;
	readonly mvrPlaceholder: string;
	readonly sourcePath?: string; // undefined for KnownPackage refs
	readonly captured?: Record<string, unknown>;
}
```

Filter on `sourcePath` if your emitter needs the Move source tree; otherwise consume every entry.

Emitters that need to read the runtime extras (`devstack({ extras })`) yield the `Extras` service
and `resolveExtras` from `@mysten-incubation/devstack/advanced` — see `StackHandleEmitter`'s source
for the pattern.

## Per-Package opt-out

`Package(name, source, { codegen: false })` excludes a package from every `Codegen(...)` in the
stack:

```ts
const internalHelper = Package('internal-helper', './move/internal', {
	signer: alice,
	codegen: false,
});
```

The Ref stamps `__codegenExclude` on itself; every `Codegen` body filters refs carrying that marker
out of the emit context.

## Errors

Every emitter failure flows through `CodegenError`:

```ts
class CodegenError extends Data.TaggedError('CodegenError')<{
	readonly emitter: string;
	readonly phase: 'read' | 'generate' | 'write';
	readonly message: string;
	readonly cause?: unknown;
}> {}
```

The `emitter` field carries the name of the emitter that failed — multi-emitter runs report which
one tripped.
