The package bin is `devstack`. Flags are command-scoped: put flags after the command that owns them.

## Command index

### `devstack up [options]`

Boot a stack and stay attached until interrupted.

Lifecycle: attached. Side effects: write. Docker: yes. Options: `--json`, `--app <name>`,
`--stack <name>`, `--state-dir <path>`, `--verbose`, `--config <path>`, `--network <name>`,
`--renderer <tui|plain|silent>`.

### `devstack apply [options]`

Boot, reconcile, emit generated files, and exit.

Lifecycle: one-shot. Side effects: write. Docker: yes. Options: `--json`, `--app <name>`,
`--stack <name>`, `--state-dir <path>`, `--verbose`, `--config <path>`, `--network <name>`.

### `devstack status [options]`

Show the persisted stack projection.

Lifecycle: offline. Side effects: read. Docker: no. Options: `--json`, `--app <name>`,
`--stack <name>`, `--state-dir <path>`, `--verbose`.

### `devstack doctor [options]`

Run host and stack preflight checks.

Lifecycle: offline. Side effects: read. Docker: yes. Options: `--json`, `--app <name>`,
`--stack <name>`, `--state-dir <path>`, `--verbose`.

### `devstack config [options]`

Print resolved config inputs.

Lifecycle: offline. Side effects: read. Docker: no. Options: `--json`, `--app <name>`,
`--stack <name>`, `--state-dir <path>`, `--verbose`, `--config <path>`, `--network <name>`.

### `devstack schema --json`

Emit the CLI schema.

Lifecycle: offline. Side effects: none. Docker: no. Options: `--json`.

### `devstack snapshot <command> [options]`

Capture, restore, list, or delete stack snapshots.

Lifecycle: offline. Side effects: write. Docker: yes. Options: none.

### `devstack snapshot save [id] [--label <label>] [options]`

Capture a snapshot through a one-shot stack boot.

Lifecycle: one-shot. Side effects: write. Docker: yes. Arguments: `id`. Options: `--json`,
`--app <name>`, `--stack <name>`, `--state-dir <path>`, `--verbose`, `--config <path>`,
`--network <name>`, `--label <label>`.

### `devstack snapshot restore <id-or-label> [options]`

Restore a snapshot by id or label.

Lifecycle: offline. Side effects: destructive. Docker: yes. Arguments: `id-or-label`. Options:
`--json`, `--app <name>`, `--stack <name>`, `--state-dir <path>`, `--verbose`.

### `devstack snapshot list [options]`

Lifecycle: offline. Side effects: read. Docker: no. Options: `--json`, `--app <name>`,

### `devstack snapshot delete <id-or-label> [options]`

### `devstack prune [--list | --dry-run | --all --yes] [options]`

Lifecycle: offline. Side effects: destructive. Docker: yes. Options: `--json`, `--app <name>`,

## Lifecycle commands

```bash
devstack up --renderer tui
devstack apply
```

`up` boots the stack and stays attached until you quit the TUI or interrupt the process. `apply`
boots, reconciles, emits generated files, and exits for CI or one-shot local workflows.

Both commands accept `--config <path>`, `--network <name>`, `--app <name>`, `--stack <name>`,
`--state-dir <path>`, `--json`, and `--verbose`. Only `up` accepts `--renderer tui|plain|silent`.

## Inspection commands

```bash
devstack status --json
devstack doctor
devstack config
devstack schema --json
```

`status` reads the persisted projection without requiring a running stack. `doctor` runs host
preflight checks. `config` prints resolved config inputs. `schema --json` prints the command tree
and exit-code table consumed by automation.

## Snapshot commands

```bash
devstack snapshot save [id] --label before-migration
devstack snapshot list
devstack snapshot restore <id-or-label>
devstack snapshot delete <id-or-label>
```

`snapshot save` performs a one-shot stack boot and can accept `--config <path>`. `snapshot restore`
and `wipe` refuse to mutate state while an attached `devstack up` session is live. `snapshot list`
and `snapshot delete` operate on the selected stack root.

## Cleanup commands

```bash
devstack prune --dry-run
devstack prune --yes
devstack wipe --dry-run
devstack wipe --yes
```

`prune` runs cross-stack orphan cleanup without requiring a running stack. `wipe` removes all state
for the selected stack after confirmation.
