The `devstack` binary ships with the package. `pnpm dev` in a
scaffolded app runs `devstack up` under the hood.

## `devstack up`

Boot the stack described by `./devstack.config.ts` and run until
interrupted.

```bash
devstack up                            # default — interactive TUI
devstack up --renderer plain           # one-line-per-event stream (CI, piped output)
devstack up --renderer silent          # no output
DEVSTACK_STACK=test devstack up        # per-stack state (parallel-safe)
```

The supervisor:

1. Acquires every Ref in the config's stack in dependency order.
2. Writes `.devstack/manifest.json` (or `.devstack/stacks/<stack>/manifest.json`
   for non-default stacks) on every state change.
3. Watches paths declared via `provide(..., {watch})` plus
   `config.watch` and hot-restarts the affected primitives.
4. Holds containers open on a long-lived scope so press-`r`
   full-restart keeps `sui.localnet` and similar reusable containers
   alive across cycles.

TUI keybindings:

- `r` — full restart.
- `R` — full restart (alias).
- `q` — graceful shutdown.
- Ctrl-C — graceful shutdown (also catches signals from outside the
  TUI).

## `devstack apply`

Acquire the stack once, emit the manifest, and exit immediately. Use
for non-interactive contexts (CI seeding, build pipelines) that just
need the side effects.

```bash
devstack apply
DEVSTACK_STACK=ci devstack apply
```

The supervisor still tears down its scope on exit; reusable containers
on `longLivedScope` stay alive so the next `apply` (or `up`) adopts
them.

## `devstack stack`

Manage per-stack state.

```bash
devstack stack list                    # which stacks exist on this <app, network>?
devstack stack down [stack]            # tear down containers + clear state
devstack stack ls                      # alias for `list`
```

State lives under `.devstack/stacks/<stack>/`. `stack down` removes
containers labelled `devstack.stack=<stack>` plus the state dir.

## `devstack wipe`

Remove every devstack-owned container and named volume on the host,
regardless of `<app, stack, network>`. Use as a nuclear option when
you want a clean docker daemon.

```bash
devstack wipe
devstack wipe --yes                    # skip confirmation
```

## `devstack doctor`

Diagnostic checks for common setup issues — docker daemon health, sui
binary version, port availability, lockfile staleness.

```bash
devstack doctor
```

Each check is `OK` / `WARN` / `FAIL` with a hint for how to fix it.

## `devstack prune`

Reclaim disk from stopped stacks across every repo on the host.

```bash
devstack prune                         # interactive — pick which to remove
devstack prune --all --yes             # remove everything not currently running
```

The host-wide registry under `~/.devstack/registry.json` tracks every
stack ever booted on this host, so `prune` finds stale ones even after
the repo that created them is deleted.

## Environment variables

- `DEVSTACK_STACK` — override `config.stackName` for this invocation.
  Layers under `.devstack/stacks/<stack>/`.
- `DEVSTACK_APP_DIR` — pin the working directory the supervisor
  treats as the repo root. Default is `process.cwd()`.
- `DEVSTACK_NO_ROUTER` — skip the shared Traefik router boot. Useful
  for tests that don't go through docker, or as an emergency switch
  if `*.localhost` resolution is misbehaving.
