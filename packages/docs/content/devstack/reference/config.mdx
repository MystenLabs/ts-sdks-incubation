## `defineDevstack`

```ts
import { defineDevstack } from '@mysten-incubation/devstack';

export default defineDevstack(stack, options);
// or
export default defineDevstack({ stack, ...options });
```

Returns a `Devstack` object:

```ts
interface Devstack {
	readonly layer: Layer.Layer<unknown, unknown, never>;
	readonly config: DevstackConfig;
	readonly run: (overrides?: RunOverrides) => Promise<void>;
	readonly runMain: (overrides?: RunOverrides) => void;
	readonly launchEffect: (overrides?: RunOverrides) => Effect.Effect<void, unknown, never>;
}
```

- **`layer`** — the composed layer (for use inside test fixtures or with `Effect.provide`).
- **`run()`** — launches the stack as a Promise that resolves on clean shutdown.
- **`runMain()`** — launches via `NodeRuntime.runMain` — handles signals, exit codes, fatal
  reporting. Best for CLI entry points (and what `devstack up` calls).
- **`launchEffect()`** — the raw launch Effect for callers that want to `yield*` it inside
  their own runtime (so SIGINT propagates correctly to scope finalizers).

### `DevstackConfig`

| Option         | Type                              | Default                  | Notes                                                                |
| -------------- | --------------------------------- | ------------------------ | -------------------------------------------------------------------- |
| `stack`        | `ReadonlyArray<StackMember>`      | (required)               | The primitive tags to compose. Order = authoring order in the TUI.   |
| `stateDir`     | `string`                          | `.devstack`              | State root.                                                          |
| `stackName`    | `string`                          | `'main'`                 | Partitions state under `.devstack/stacks/<name>/`.                   |
| `network`      | `'localnet' \| 'testnet' \| 'mainnet'` | `'localnet'`        | Drives state-file layout.                                            |
| `renderer`     | `'tui' \| 'plain' \| 'silent'`    | `tui` on TTY else `plain` | Status renderer for `run()`.                                       |
| `watch`        | `ReadonlyArray<string>`           | `[]`                     | Extra paths to watch. `publishMove` already auto-watches its tree.   |
| `hotRestart`   | `boolean`                         | `true` if `watch` set    | Whether file-watch events trigger a full restart.                    |

`tui: boolean` is still accepted but **deprecated** — pass `renderer:` instead.

### `RunOverrides`

```ts
devstack.run({ renderer: 'plain' });
```

Currently just `{ renderer }`. The CLI's `--renderer` flag wins over the config's default; the
overrides argument is what `devstack up --renderer plain` injects.

## `provideDevstack`

```ts
import { provideDevstack } from '@mysten-incubation/devstack';

const layer = provideDevstack(stack, options);
```

Returns the same composed `Layer.Layer<unknown, unknown, never>` as `Devstack.layer` — without
the launch loop / TUI / watcher. Use with `Effect.provide`.

`options` is the subset of `DevstackConfig` that affects layer composition:

| Option              | Type                       | Default       | Notes                                                                |
| ------------------- | -------------------------- | ------------- | -------------------------------------------------------------------- |
| `stackName`         | `string`                   | `'main'`      | Same as `defineDevstack`.                                            |
| `network`           | `SuiNetwork`               | `'localnet'`  | Same.                                                                |
| `stateDir`          | `string`                   | `.devstack`   | Same.                                                                |
| `platformLayer`     | `Layer<unknown, unknown, never>` | `NodeServicesLayer` | Override platform services. Integration tests only.            |
| `infraOverrides`    | `Layer<unknown, unknown, never>` | none      | Replace one or more infra services. Integration tests only.          |

Apart from those, the consumer-shape is identical to `defineDevstack`. See the [Effect
programs](/devstack/guides/effect-programs) guide for usage patterns.

## `composeStackLayer`

Lower-level form of the same composition step. Returns the user-stack-plus-infra-plus-platform
layer without `provideDevstack`'s API affordances. Used by both `defineDevstack` and
`provideDevstack` internally; available for advanced cases (e.g. a custom long-running
supervisor of your own).

```ts
import { composeStackLayer } from '@mysten-incubation/devstack';

const layer = composeStackLayer(stack, {
	stackName: 'main',
	network: 'localnet',
});
```

## Where it goes on disk

The supervisor writes under `.devstack/` at the root of the project that contains the config:

```
.devstack/
├── active                           # stack name (informational)
├── stacks/
│   └── <stack>/
│       ├── state.json               # primitive cache (packageIds, port leases, etc.)
│       ├── state.json.lock          # held while a supervisor is running
│       ├── manifest.json            # written by `manifest()`
│       ├── .keys/<name>.key         # ephemeral-funded account keys
│       └── .seal/...                # local seal master key + config
├── networks/                        # state for live-net stacks (testnet/mainnet)
└── imports/                         # gitFetch'd Move sources
```

Everything under `.devstack/` is regenerable — git-ignore it. `devstack wipe` clears the
per-stack subtree; `devstack prune` clears across stacks.
