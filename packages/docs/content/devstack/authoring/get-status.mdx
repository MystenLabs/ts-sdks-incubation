---
title: getStatus
description: How the reconciler decides whether to run an action.
---

Each action provides `getStatus?(ctx) => Promise<{ ok: boolean; detail?: string }>`. The reconciler
walks the topo order, asks each action whether it's converged, and only runs work that has actually
drifted. Skip predicate logic per action:

- Hash mismatch + no `getStatus` → run.
- Hash mismatch + `getStatus.ok === true` (cold cycle) → skip.
- Hash match + no `getStatus` → skip.
- `getStatus.ok === true` → skip.
- `getStatus.ok === false` → run.

Plus: `Emit` actions re-fire when a kind in their `dependsOnKind` slice was dirtied during the
cycle, even if their own input hash matched.

## Cold-cycle hydration

The reconciler consults `getStatus` first when defined, even on a cold cycle (no prior input hash in
memory). Plugins that hydrate state from the manifest (seal's cached `KeyServer` objectId,
sui.localnet's running container, walrus's deploy volume) can short-circuit expensive re-runs on
supervisor restart.

## Capabilities

`provides: ['cap-name']` and `needs: ['cap-name:before']` (or `:after`) express cross-plugin
ordering without pinning to a specific action name. Soft — a capability query against a missing
provider is silently dropped, so plugins that may or may not be loaded compose cleanly.

When multiple actions provide the same capability, ordering between siblings is unspecified. Avoid
relying on it.

## File watcher

`watches?: string[]` extends the file watcher's coverage. Default inferred globs:

- `Publish` — `<path>/Move.toml`, `<path>/sources/**`.
- `Build` — `<inputs.dockerfile>`, `<inputs.context>`.

Use `watches:` for non-Move-package inputs (GraphQL schemas, JSON configs, generated SDLs). Paths
resolve against `appDir` and may use glob syntax. The watcher unions inferred globs with `watches`.
