The same `devstack.config.ts` boots the stack your tests run against.
No mock layer — your e2e and unit tests both exercise the real
localnet, real packages, real funded accounts.

## Vitest

`@mysten-incubation/devstack/vitest` exports `devstackTest(config)` —
a fixture that boots the stack once per file and tears it down
after.

```ts
// tests/balance.test.ts
import { describe, expect } from 'vitest';
import { devstackTest } from '@mysten-incubation/devstack/vitest';
import config from '../devstack.config.js';

const test = devstackTest(config);

describe('alice', () => {
	test('receives funding at boot', async ({ stack }) => {
		const alice = await stack.account('alice');
		const balance = await stack
			.client()
			.getBalance({ owner: alice.address });
		expect(BigInt(balance.totalBalance)).toBeGreaterThan(0n);
	});

	test('can publish her own package', async ({ stack }) => {
		const hello = await stack.package('hello');
		expect(hello.packageId).toMatch(/^0x/);
	});
});
```

`{ stack }` carries:

- `stack.account(name)` → resolved `AccountShape`.
- `stack.package(name)` → resolved `LocalPackageShape`.
- `stack.client()` → `SuiJsonRpcClient` against the local RPC.
- `stack.manifest()` → the v4 `Manifest` value.

The fixture runs against a per-stack-name partition. Default is the
file's basename; override with `DEVSTACK_STACK=foo pnpm test`. Parallel
test files get their own stack each, so docker containers don't
collide.

## Playwright

`@mysten-incubation/devstack/playwright` exports
`playwrightWebServer(opts)` for the Playwright `webServer` config and
`connectAs(page, account)` for in-test account switching:

```ts
// playwright.config.ts
import { defineConfig } from '@playwright/test';
import { playwrightWebServer } from '@mysten-incubation/devstack/playwright';

export default defineConfig({
	webServer: playwrightWebServer({ endpoint: 'dev-server' }),
	use: { baseURL: 'http://dev.my-app.localhost' },
});
```

`playwrightWebServer` reads `.devstack/manifest.json` for the URL,
so Playwright never races the supervisor for port allocation. The
endpoint discriminator picks which app the webServer points at —
`'dev-server'` for the Vite dev server, `'wallet-app'` for the
wallet UI.

In tests:

```ts
import { test, expect } from '@playwright/test';
import { connectAs } from '@mysten-incubation/devstack/playwright';

test('alice can sign in', async ({ page }) => {
	await page.goto('/');
	await connectAs(page, 'alice');
	await expect(page.getByRole('button', { name: /alice/i })).toBeVisible();
});
```

`connectAs` drives the dapp-kit account switch via the bridge devstack
exposes on `globalThis.__devstackDAppKit__` in dev/preview/playwright
mode.

## Running tests in CI

```bash
pnpm test                              # vitest
pnpm test:e2e                          # playwright
```

Both honor `DEVSTACK_STACK`. CI typically:

1. Sets `DEVSTACK_STACK=ci-${jobId}` so concurrent jobs don't
   collide.
2. Runs `devstack apply` to boot the stack non-interactively.
3. Runs `pnpm test` / `pnpm test:e2e` against the booted stack.
4. Runs `devstack stack down ci-${jobId}` to clean up.

Or — for a fresh stack per test file — let `devstackTest` boot and
tear down per-file. The trade-off is wall-clock time (cold sui-localnet
boot ~10-30s) vs isolation; `pnpm test:e2e` typically uses one stack
for all files, `pnpm test` per-file.
