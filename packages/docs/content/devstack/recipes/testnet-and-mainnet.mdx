---
title: Testnet and mainnet
description: Run the same config against a live network.
---

The same `devstack.config.ts` runs against testnet and mainnet — only
the source of each Ref changes. The shape downstream code consumes
(packageIds, endpoints, account addresses) stays identical.

## Switching networks

`Sui({network: 'testnet'})` or `Sui({network: 'mainnet'})` swap the
RPC + faucet for the public ones. Localnet-only Refs
(`walrusLocalCluster`, `Seal({mode: 'local'})`) get their `'known'`
variant instead:

```ts
import { devstack, Sui, Account, Walrus, Seal, KnownPackage } from '@mysten-incubation/devstack';

const network = process.env.DEVSTACK_NETWORK ?? 'localnet';

const alice = Account('alice', {
	from: network === 'localnet' ? 'ephemeral-funded' : 'env',
	...(network === 'localnet' ? {} : { key: 'ALICE_PRIVATE_KEY' }),
});

const deepbook = KnownPackage('deepbook', {
	packageId: '0xdee...',                              // testnet deepbook
	mvrPlaceholder: '@mvr/deepbook',
});

export default devstack(
	Sui({ network }),
	Walrus({ mode: network === 'localnet' ? 'local' : 'known' }),
	Seal({ mode: network === 'localnet' ? 'local' : 'known', signer: alice }),
	alice,
	deepbook,
);
```

Then `DEVSTACK_NETWORK=testnet pnpm dev` boots against testnet.
`DEVSTACK_STACK=staging-testnet DEVSTACK_NETWORK=testnet pnpm dev`
isolates state under `.devstack/networks/testnet.json` so multiple
testnet stacks coexist.

## State partitioning

State files separate by network:

- `localnet` → `.devstack/stacks/<stack>/state.json` (and the
  per-stack-scoped manifest under the same path).
- `testnet` / `mainnet` → `.devstack/networks/<network>.json` (no
  per-stack split — there's only one testnet).

Per-Account ephemeral keys persist under the localnet path so the
same address resurfaces across `docker rm`. On testnet/mainnet the
keystore/env source is the only viable choice — there's no faucet to
re-fund a fresh key.

## Codegen against live data

`Bindings` / `Codegen` work the same against any network. The
emitter reads the resolved package set — mix `Package(...)` and
`KnownPackage(...)` freely:

```ts
import { Bindings, Package, KnownPackage } from '@mysten-incubation/devstack';

const myCoin = Package('mycoin', './move/mycoin', { signer: alice });
const deepbook = KnownPackage('deepbook', { packageId: '0xdee...', mvrPlaceholder: '@mvr/deepbook' });

// Bindings emits for `myCoin` (Move source available); skips
// `deepbook` (no source). DappKit's MVR overrides include both.
Bindings({ packages: [myCoin], output: './src/generated' });
```

## Migration checklist

When promoting a localnet config to live:

1. Swap `Sui({network: 'localnet'})` for `'testnet'` / `'mainnet'`.
2. Switch every `Account()` source from `'ephemeral-funded'` to
   `'env'` or `'keystore'`. Move funding to your CI / deploy
   pipeline.
3. Replace `Walrus()` / `Seal()` / `Deepbook()` local defaults with
   `{mode: 'known'}`.
4. Add `KnownPackage(...)` entries for any third-party packages your
   app reads from (deepbook, walrus, seal — already wired internally
   for the composite Refs).
5. Set `DEVSTACK_STACK` per environment so artifacts don't collide
   under `.devstack/`.
