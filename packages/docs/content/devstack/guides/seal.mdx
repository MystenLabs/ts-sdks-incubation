title: Seal
---

Seal is Sui's threshold-encryption layer — clients encrypt data against a policy expressed in
Move, and a key server decrypts (or refuses) based on the on-chain policy check. Devstack ships
`sealLocalKeygen()` for a local Open-mode key server and `sealKnownKeyServer()` for a handle to
a public one.

## Local key server

```ts
import { sealLocalKeygen, SealKeyServer } from '@mysten-incubation/devstack';

const a = accounts({ publisher: {}, alice: {} });

const sl = sealLocalKeygen({
	signer: a.publisher,
});

const m = manifest({
	extras: Effect.gen(function* () {
		const ks = yield* SealKeyServer;
		return {
			sealKeyServer: {
				objectId: ks.objectId,
				url: ks.keyServerUrl,
			},
		};
	}),
});

export default defineDevstack([
	suiLocalnet(),
	a.publisher,
	sl,
	m,
]);
```

`sealLocalKeygen`:

1. Builds the Seal Docker image (~5–8 min cold).
2. Runs `seal-cli genkey` to mint a fresh master keypair, persists it under
   `.devstack/stacks/<stack>/.seal/` so warm starts reuse the same key server identity.
3. Fetches the Seal Move package source at the pinned ref, publishes it as `signer`.
4. Registers a `KeyServer` object on chain with the master public key.
5. Renders the key-server YAML config, starts the container.
6. Provides two interface tags: **`SealKeyServer`** (read surface — URL + object id, safe to
   expose to frontends) and **`SealKeyManager`** (local-only admin — master-key env-file path
   plus a rotate Effect).

The dual-tag split matters: code that only needs to talk to the running server depends on
`SealKeyServer`. Code that rotates keys depends on `SealKeyManager`. A `sealKnownKeyServer()`
swap-in provides `SealKeyServer` only — `SealKeyManager` is local-keygen-specific by design.

### Surfacing the key server URL to the frontend

The frontend needs the key server's URL and object id to build a `SealClient`. The pattern is
to read them off `SealKeyServer` inside `manifest({ extras })`:

```ts
const m = manifest({
	extras: Effect.gen(function* () {
		const ks = yield* SealKeyServer;
		return {
			sealKeyServer: { objectId: ks.objectId, url: ks.keyServerUrl },
		};
	}),
});
```

`manifest.extras.sealKeyServer` is now in `.devstack/manifest.json` and reachable from your
dapp-kit module.

## Pin the dev server behind seal acquire

Use `dependsOn:` to ensure your Vite/Next dev server doesn't accept traffic before the key
server is ready:

```ts
const dev = hostProcess({
	name: 'frontend.dev-server',
	command: 'pnpm',
	args: ['exec', 'vite'],
	dependsOn: [vaultPublish, SealKeyServer as never, wallet],
	// ...
});
```

`SealKeyServer` is yieldable as a `dependsOn` entry — the supervisor yields each entry for
ordering and discards the value, so you cast the interface tag through `as never` to satisfy
the `PluginTag<…>[]` slot.

## Known key server

```ts
import { sealKnownKeyServer } from '@mysten-incubation/devstack';

const sk = sealKnownKeyServer({ network: 'testnet' });
```

Provides `SealKeyServer` only (defaults pulled from `knownDeployments.seal`). Useful when you
want to consume Seal's testnet deployment without running the heavy local image — typical for
hybrid stacks where Sui itself is local but Seal is remote.

## What's in each interface

| Interface tag      | Shape                                                                          |
| ------------------ | ------------------------------------------------------------------------------ |
| `SealKeyServer`    | `{ objectId, keyServerUrl, publicKey }` — what a `SealClient` needs.            |
| `SealKeyManager`   | `{ envFilePath, rotate: Effect.Effect<void, …> }` — local-only admin surface.   |

## Common pitfalls

- **Image build time** — `sealLocalKeygen` builds a native-arch container image. First build
  takes 5–8 min on Apple Silicon. Cached after that, but CI without a warm cache should pre-build.
- **Master key persists across `devstack wipe`** — the key keypair lives under
  `.devstack/stacks/<stack>/.seal/` outside the `state.json` cache, so a `wipe` doesn't
  re-mint. If you want a fresh server identity, delete the directory manually.
- **`SealKeyManager` not resolvable** — you're using `sealKnownKeyServer` which only provides
  `SealKeyServer`. Switch to `sealLocalKeygen` if you need the admin surface (it's
  local-keygen-specific by design).
