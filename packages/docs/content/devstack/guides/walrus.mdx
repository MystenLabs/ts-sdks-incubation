title: Walrus

Walrus is Sui's decentralized blob storage. Devstack ships two primitives:
`walrusLocalCluster()` for a full local committee, and `walrusKnownDeployment()` for a handle to
the public testnet deployment.

## Local cluster

```ts
import { walrusLocalCluster } from '@mysten-incubation/devstack';

const a = accounts({ publisher: {}, alice: {}, bob: {} });

const w = walrusLocalCluster({
	nodeCount: 4,
	seedAccounts: [a.publisher, a.alice, a.bob],
});

export default defineDevstack([
	suiLocalnet(),
	a.publisher,
	a.alice,
	a.bob,
	w,
	manifest(),
]);
```

What `walrusLocalCluster` does on acquire:

1. **Builds the wrapper Docker image** (~10 min cold; cached after). The image bakes a pinned
   Sui binary so the deploy script can sign as the admin wallet.
2. **Fetches the Walrus Move sources** at a pinned ref (overridable via `movePackagePath:` if
   you've vendored a copy).
3. **Deploys the Walrus contracts** on local Sui as a one-shot.
4. **Registers each storage node** on chain and brings up `nodeCount` storage-node containers
   (default 4). Each binds the container API port; the shared Traefik router fronts them on
   host port 9185 by `Host:` header.
5. **Swaps SUI → WAL** for every seed account (default 0.5 SUI per account).
6. **Provides four interface tags**: `WalrusNetwork`, `WalrusNodes`, `WalrusProxy`,
   `WalrusAdmin`. Downstream consumers depend on the interface, not the factory, so swapping
   in a known deployment is a one-line edit.

The Move package is captured into the manifest as `walrus.walrus` carrying `systemObject` and
`stakingObject` in `captured`.

### Options

| Option                | Default            | Notes                                                                  |
| --------------------- | ------------------ | ---------------------------------------------------------------------- |
| `nodeCount`           | 4                  | Storage-node committee size.                                           |
| `shards`              | 100                | Must be ≥ `nodeCount`.                                                 |
| `seedAccounts`        | `[]`               | Each gets 0.5 SUI swapped to WAL on bring-up. Pass `accounts({...})` tags. |
| `seedPaymentMist`     | `500_000_000n`     | SUI swapped per seed account, in MIST.                                 |
| `epochDuration`       | `'24h'`            | Walrus epoch duration.                                                 |
| `version`             | `'walrus-v1.39.0'` | Pinned upstream tag. Drives both Docker image and Move source fetch.   |
| `movePackagePath`     | `undefined`        | Override the Move source fetch with a local vendored path.             |
| `readyTimeoutMs`      | `60_000`           | Per-node ready-probe timeout.                                          |

## Frontend integration

`@mysten-incubation/devstack/dapp-kit` ships a helper that returns the `WalrusClient` config:

```ts
import { localnetWalrusOptions } from '@mysten-incubation/devstack/dapp-kit';
import { WalrusClient } from '@mysten/walrus';

const walrusClient = new WalrusClient({
	suiClient,
	...localnetWalrusOptions(manifest),
	wasmUrl,
});
```

`localnetWalrusOptions` reads `manifest.packages` to find the walrus deployment's
`systemObjectId` / `stakingPoolId` and pins `storageNodeUrlScheme: 'http'` (devstack nodes serve
plain HTTP). It throws with a helpful message if the manifest hasn't been written yet (e.g. the
stack is still acquiring).

## Known deployment (testnet)

Same code, swap one line:

```ts
import { walrusKnownDeployment } from '@mysten-incubation/devstack';

const w = walrusKnownDeployment({ network: 'testnet' });
```

`walrusKnownDeployment` provides only `WalrusNetwork` (read URLs) — there's no local
admin/proxy/nodes infrastructure to expose. Code that depends on `WalrusNetwork` only (typical
read paths) works against both factories without modification. Code that yields
`WalrusAdmin` / `WalrusNodes` only resolves against `walrusLocalCluster`.

## What's in each interface

| Interface tag    | Shape                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------- |
| `WalrusNetwork`  | `{ proxyUrl, systemObjectId, stakingPoolId, suiPackageId }` — every URL/id a client needs. |
| `WalrusNodes`    | `{ nodes: ReadonlyArray<WalrusNodeInfo> }` — per-node API URLs + public keys.          |
| `WalrusProxy`    | `{ url }` — single nginx-proxied URL fronting the cluster.                              |
| `WalrusAdmin`    | `{ adminAccount, signAdminTx, … }` — local-cluster-only.                                |

## Common pitfalls

- **First-build time** — building the Walrus image is the slowest part of any devstack boot
  (~10 min on Apple Silicon). The image caches after the first run; CI environments without a
  warm cache should pre-build it as a separate step.
- **Move source pin drift** — `walrusLocalCluster` fetches Walrus's Move source at the version
  pinned by `version:`. If you're testing against a vendored Walrus checkout, pass
  `movePackagePath:` so the supervisor uses your tree instead.
- **Shards < nodes** — the supervisor refuses to boot. Walrus's deploy script needs at least
  one shard per node.
- **Seed accounts without faucet funding** — the swap step pays SUI to mint WAL. Seed accounts
  must be funded before walrus acquires; the default `ephemeral-funded` accounts handle this
  automatically, but `env`/`keystore`/`inline` sources need out-of-band funding.
