title: E2E with Playwright

Devstack ships a `@mysten-incubation/devstack/playwright` subpath that wires Playwright to a
running devstack: `webServer` boots the supervisor and waits for the dev-server endpoint,
`baseURL` reads the same endpoint into `use.baseURL`, and `connectAs(page, 'alice')` clicks
through the wallet modal and retargets dApp Kit to the named account.

## `playwright.config.ts`

```ts
import { defineConfig, devices } from '@playwright/test';
import { baseURL, webServer } from '@mysten-incubation/devstack/playwright';

export default defineConfig({
	testDir: './e2e',
	fullyParallel: false,
	workers: 1,
	forbidOnly: !!process.env.CI,
	retries: process.env.CI ? 2 : 0,
	reporter: process.env.CI ? [['github'], ['list']] : 'list',
	webServer: webServer({ endpoint: 'dev-server', timeout: 300_000 }),
	use: {
		baseURL: baseURL({ endpoint: 'dev-server' }),
		trace: 'on-first-retry',
		screenshot: 'only-on-failure',
	},
	projects: [{ name: 'chromium', use: { ...devices['Desktop Chrome'] } }],
});
```

- **`webServer({ endpoint })`** reads `.devstack/manifest.json`, looks up the named endpoint, and
  builds Playwright's `webServer` config. The default `command:` is `pnpm dev`, which runs
  `devstack up`. `reuseExistingServer: true` (default outside CI) lets you run `pnpm dev` in one
  terminal and `pnpm test:e2e` in another without restarting the stack between runs.
- **`baseURL({ endpoint })`** reads the same manifest entry and returns the URL, so
  `page.goto('/')` resolves to your dev server.
- **`timeout: 300_000`** — five minutes accommodates a cold Docker build (Sui image ~5 min,
  Walrus ~10 min, Seal ~5–8 min). On warm runs the supervisor is up in seconds.

The endpoint name (`dev-server`) is whatever you set on your `hostProcess({ endpoint: { name } })`
in `devstack.config.ts`. The template uses `'dev-server'` for the Vite child.

## Writing a test

```ts
// e2e/mint.spec.ts
import { connectAs, expect, test } from '@mysten-incubation/devstack/playwright';

test('alice sends a greeting', async ({ page }) => {
	await connectAs(page, 'alice');

	await expect(page.getByTestId('package-id')).not.toHaveText('0x0');

	await page.getByTestId('mint-button').click();
	await expect(page.getByTestId('mint-tx')).toBeVisible({ timeout: 20_000 });
});
```

`connectAs(page, label)`:

1. Navigates to `/`.
2. Clicks `mysten-dapp-kit-connect-button`.
3. Picks "Dev Wallet" in the modal.
4. Asserts "Connected as …" surface is visible.
5. Switches dApp Kit's current account to the one whose label matches `label`.
6. Asserts "Connected as &lt;label&gt;" — gives you a fixed assertion to catch wiring regressions.

`label` matches the account name from `accounts({ alice: {} })`. Casing is normalized.

### Requirements

`connectAs` reaches into `globalThis.__devstackDAppKit__` to switch accounts without driving the
modal twice. `createDevstackDappKit` sets this slot automatically when running under Vite dev,
Vite preview, or with `PLAYWRIGHT=1`. If you build your dApp-Kit instance manually, expose it
yourself in `dapp-kit.ts`:

```ts
export const dAppKit = createDAppKit({ ... });
(globalThis as { __devstackDAppKit__?: typeof dAppKit }).__devstackDAppKit__ = dAppKit;
```

## Helpers

`@mysten-incubation/devstack/playwright` re-exports Playwright's `test`/`expect` plus three
helpers:

- **`connectAs(page, label)`** — modal click-through + account swap (above).
- **`selectAccount(select, name)`** — pick a `<select>` option by visible text. Useful when your
  UI exposes a per-row signer dropdown.
- **`waitForBalanceUpdate(page, name, predicate)`** — polls a `data-testid="balance-<name>"`
  cell until the predicate matches. Catch-all for "did the tx invalidate and refetch?"

```ts
import { connectAs, selectAccount, waitForBalanceUpdate, test } from '@mysten-incubation/devstack/playwright';

await waitForBalanceUpdate(page, 'alice-usdc', (text) => Number(text) > 0);
```

## Parallel workers — one stack per worker

The default `webServer` boots one supervisor. If you want multiple Playwright workers each
against an isolated stack, give each one a `DEVSTACK_STACK` and run them as separate
`playwright test` invocations:

```bash
DEVSTACK_STACK=worker1 playwright test --shard=1/2 &
DEVSTACK_STACK=worker2 playwright test --shard=2/2 &
wait
```

Each worker runs its own supervisor under its own stack name. The Traefik router routes
`dev.worker1.my-app.localhost` to one Vite instance and `dev.worker2.my-app.localhost` to
another; allocated container ports don't collide because the port allocator scans per-stack.

Per-worker fixtures inside a single Playwright invocation (Playwright's `workers: N` setting)
are not supported through `setupDevstack` — it acquires globally. If you need that, run
multiple `playwright test` processes as above.

## Out-of-band stack control

If you want Playwright itself to manage the stack lifecycle (acquire-then-release rather than
`reuseExistingServer`), use `setupDevstack` instead of `webServer`:

```ts
// playwright.config.ts
import { setupDevstack } from '@mysten-incubation/devstack/playwright';
import devstack from './devstack.config.ts';

const fixture = setupDevstack(devstack);

export default defineConfig({
	globalSetup: fixture.globalSetup,
	globalTeardown: fixture.globalTeardown,
	// ...
});
```

`globalSetup` builds the devstack layer against a long-lived scope; `globalTeardown` closes the
scope and runs every primitive's finalizer in reverse order. Useful when you want the stack
torn down between CI runs.

## Common pitfalls

- **"manifest not found at .devstack/manifest.json"** — `webServer` and `baseURL` need the
  manifest written before tests start. The default `reuseExistingServer: true` (outside CI)
  means tests assume a `pnpm dev` is already running. In CI, set the `command:` to
  `pnpm dev` (or `devstack apply` for one-shot bring-up) so Playwright owns the lifecycle.
- **"Connected as …" never appears** — usually means `globalThis.__devstackDAppKit__` isn't
  set. Confirm `createDevstackDappKit` is the path you went down; if you built dApp-Kit
  manually, expose the slot yourself.
- **The dev-server endpoint URL ends in a hostname like `dev.my-app.localhost`** —
  `*.localhost` resolves to `127.0.0.1` on every major OS. If yours doesn't, set
  `DEVSTACK_NO_ROUTER=1` and the supervisor will skip Traefik; endpoints become bare
  `http://localhost:<port>` URLs.
