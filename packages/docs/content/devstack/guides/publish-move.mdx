---
title: Publish a Move package
---

`publishMove` builds your Move source tree, publishes it on the resolved `Sui` chain, and
surfaces the result — `packageId`, `upgradeCapId`, captured object ids, an MVR placeholder, and
any coins you declared. Edits to the source tree trigger an auto-restart.

## Minimal example

```ts
const a = accounts({ alice: {} });

const helloPublish = publishMove({
	name: 'hello',
	path: resolve(HERE, 'move/hello'),
	signer: a.alice,
});

export default defineDevstack([suiLocalnet(), a.alice, helloPublish, manifest()]);
```

`helloPublish` is a tag. Yielding it inside another primitive reads the per-call shape:

```ts
const mint = tx({
	name: 'mint',
	signer: a.alice,
	dependsOn: [helloPublish],
	build: (t) =>
		Effect.gen(function* () {
			const pkg = yield* helloPublish;
			t.moveCall({ target: `${pkg.packageId}::hello::mint`, arguments: [] });
		}),
});
```

`pkg.packageId` is the freshly-published live ID. After every restart the supervisor:

- Content-hashes `**/*.move` + `Move.toml`. A hit reuses the cached `packageId` — downstream
  caches (`tx({ cacheKey })`, bindings, anything keyed on the package) stay warm.
- A miss runs `sui move build`, signs and executes a `Publish` transaction as `signer`, and
  caches the new `packageId` in `.devstack/stacks/<stack>/state.json`.

## Capture object ids from the publish tx

`capture:` runs after publish and lets you pull object ids out of the `objectChanges` array.
Common patterns: `TreasuryCap`, `Publisher`, `AdminCap`.

```ts
const usdcPublish = publishMove({
	name: 'usdc',
	path: resolve(HERE, 'move/usdc'),
	signer: a.publisher,
	capture: ({ objectChanges }) => ({
		treasuryCap: pickCreatedByTypeSuffix(objectChanges, '::coin::TreasuryCap'),
		coinMetadata: pickCreatedByTypeSuffix(objectChanges, '::coin::CoinMetadata'),
		upgradeCap: pickCreatedByTypeSuffix(objectChanges, '::package::UpgradeCap'),
	}),
});
```

`usdcPublish.captured` then carries `treasuryCap`, `coinMetadata`, and `upgradeCap`. The
manifest writer serializes captured values verbatim under `manifest.packages[].captured`, so
your frontend can read them via the same `manifest` it imported for dApp Kit setup.

## Declare published coins

The `coins:` shorthand registers freshly-published coins so the manifest and the dev-wallet
panels know about them.

```ts
const tokenStudio = publishMove({
	name: 'token-studio',
	path: resolve(HERE, 'move/token-studio'),
	signer: a.publisher,
	coins: {
		musdc: { module: 'musdc', type: 'MUSDC', decimals: 6 },
		mweth: { module: 'mweth', type: 'MWETH', decimals: 18 },
	},
});
```

Each entry produces a `PublishedCoin` keyed under `tokenStudio.coins.musdc` carrying
`fullCoinType` (`0x<pkg>::musdc::MUSDC`) and `sdkCoin` (the `{ address, type, scalar }` shape
the SDK expects). The manifest writer emits them under `manifest.coins`.

## File watching and hot restart

`publishMove` auto-declares its `path:` as a watch target. Edits to `**/*.move` or `Move.toml`
fire a debounced restart of the whole stack. The supervisor logs which primitive owned the
changed path, so the TUI tells you _why_ it's restarting:

```
file change at move/hello/sources/hello.move (kind=change, content changed) — owned by hello — restarting
```

To disable hot-restart while still seeing the diagnostic, pass `hotRestart: false` to
`defineDevstack`. To add extra watch paths (e.g. a generated Move dependency the auto-detector
doesn't see), pass them on `defineDevstack({ watch: [...] })`.

## Generate TypeScript bindings

`bindings({ packages, output })` runs `sui move summary` against each published package, hands
the output to `@mysten/codegen`, and writes typed wrappers under `output/`. The dir swap is
atomic — Vite never observes a half-written tree.

```ts
import { bindings } from '@mysten-incubation/devstack';

const helloBindings = bindings({
	packages: [helloPublish],
	output: 'src/generated/hello',
});

export default defineDevstack([
	suiLocalnet(),
	a.alice,
	helloPublish,
	helloBindings, // re-runs on republish
	manifest(),
]);
```

Now `src/generated/hello/` carries typed Move-call wrappers, regenerated on every republish.

## Common pitfalls

- **`sui` CLI missing on `PATH`** — `publishMove` shells out to `sui move build`. Install the
  Sui CLI on the host even though localnet itself runs in Docker.
- **Stale `build/` directory in your Move tree** — devstack ignores `build/` when hashing, so
  the cache key stays correct, but the Sui CLI itself can occasionally trip on a stale Move
  lock file. Devstack scrubs cached `Move.lock` files before each build; if you still see
  problems, `rm -rf move/<pkg>/build` and re-run.
- **`packageId` keeps changing across restarts** — usually means the Sui localnet container
  was wiped and chain regenesis happened. The state-store cache folds in the chain id; a new
  genesis invalidates the cache and a fresh publish gets a new ID. To keep the chain alive
  across restarts, don't pass `--rm` style flags or run `devstack wipe`.
