---
title: Live Networks
description: Running the same stack shape against public networks.
---

Pick a Sui mode explicitly when the config should not default from `DEVSTACK_NETWORK`.

```ts
import { defineDevstack, sui, account, knownPackage, wallet } from '@mysten-incubation/devstack';

const alice = account('alice', {
	kind: 'env',
	key: 'ALICE_PRIVATE_KEY',
});

const registry = knownPackage('registry', {
	packageId: '0x...',
});
const liveSui = sui({ mode: 'live', network: 'testnet' });
const devWallet = wallet({ accounts: [alice] });

export default defineDevstack({
	members: [liveSui, registry, devWallet],
	stackName: 'testnet',
});
```

The CLI can also set the network before config import:

```bash
devstack up --network testnet
devstack up --network mainnet
```

Forked-network mode is coming soon. Local-only services may refuse live modes. Use the mode-specific
factories when you want the type system to narrow available branches:

```ts
import { chainId, walrusFor, sealFor, deepbookFor } from '@mysten-incubation/devstack';

const live = { mode: 'live', chain: chainId('sui:testnet') } as const;

const wal = walrusFor(live).known({
	systemObjectId: '0x...',
	stakingPoolId: '0x...',
	nodes: [],
});

const keyServer = sealFor(live).testnet({
	objectId: '0x...',
	keyServerUrl: 'https://example.test/key',
});

const dex = deepbookFor(live).known({
	packageId: '0x...',
	registryId: '0x...',
});
```

Live accounts should use `env`, `keystore`, `inline`, `signer`, or `impersonate` as appropriate. The
default ephemeral form is designed for local development, not custody of real assets.
