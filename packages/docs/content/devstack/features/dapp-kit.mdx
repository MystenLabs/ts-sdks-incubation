---
title: dapp-kit integration
description:
  A three-line `src/dapp-kit.ts` spreads the generated devstack config into `createDAppKit` — RPC
  URL, MVR overrides, and dev wallet adapter all baked in at codegen time.
---

dapp-kit wants a bunch of dev-environment-specific config: which network is the default, what RPC
URL goes with `'localnet'`, which MVR placeholders map to which package ids, and which wallets are
available. In a hand-wired setup, every one of those has to update when you regenesis the chain,
when you republish, when you switch networks.

Devstack solves this by **emitting** the dapp-kit config from `Codegen()` into your project, then
you spread it into a hand-written `createDAppKit({...})` call in `src/dapp-kit.ts`. You stay in
charge of the kit's construction — devstack stays out of your production bundle.

## Setup

```ts
// src/dapp-kit.ts (user-owned, hand-written)
import { createDAppKit } from '@mysten/dapp-kit-react';
import { devstackDappKitConfig } from './generated/dapp-kit-config.js';

export const dAppKit = createDAppKit({
	...devstackDappKitConfig,
	// app-specific overrides go here (real wallet adapters for production,
	// custom RPC selection, etc.)
});

// Expose for the playwright `connectAs` helper.
(globalThis as { __devstackDAppKit__?: typeof dAppKit }).__devstackDAppKit__ = dAppKit;

declare module '@mysten/dapp-kit-react' {
	interface Register {
		dAppKit: typeof dAppKit;
	}
}
```

That's the whole frontend wiring. Use `useDAppKit()`, `useCurrentAccount()`, and friends as normal.

The generated `devstackDappKitConfig` carries:

- **`defaultNetwork` / `networks`** — the network the supervisor pinned (`'localnet'` by default).
- **`createClient`** — a `SuiGrpcClient` factory baked with the resolved RPC URL and MVR overrides
  built from every `Package(...)` that emitted an `mvrPlaceholder`.
- **`walletInitializers`** — the devstack burner-wallet adapter wired to the resolved accounts.

## Network is set by the supervisor

The generated config reads the network from the manifest's `services.sui.network` field — whatever
`--network` the supervisor booted with. `pnpm dev` defaults to localnet;
`devstack up --network testnet` regenerates the config for testnet. No per-network user wiring, and
no `additionalNetworks` array to keep in sync.

The wallet baked in is the devstack dev wallet — useful during development against any network, but
**not what you want to ship to production**. For production deploys, override `walletInitializers`
in your `createDAppKit({...})` spread with your real wallet initializers (Slush, Suiet, etc.):

```ts
import { createDAppKit } from '@mysten/dapp-kit-react';
import { devstackDappKitConfig } from './generated/dapp-kit-config.js';
import { slushWalletInitializer } from '@mysten/slush-wallet';

export const dAppKit = createDAppKit({
	...devstackDappKitConfig,
	walletInitializers: import.meta.env.PROD
		? [slushWalletInitializer()]
		: devstackDappKitConfig.walletInitializers,
});
```

## Customising the burner wallet

The generated config exports a `devstackWalletInitializer(opts)` factory for apps that want to tweak
the burner-wallet behaviour (headless mounting, auto-approve, …) without rebuilding the adapter from
scratch:

```ts
import { createDAppKit } from '@mysten/dapp-kit-react';
import { devstackDappKitConfig, devstackWalletInitializer } from './generated/dapp-kit-config.js';

// Drop the wallet's panel UI from the production bundle (~30KB saving).
const headlessInit = devstackWalletInitializer({ mountUI: false });

export const dAppKit = createDAppKit({
	...devstackDappKitConfig,
	walletInitializers: headlessInit ? [headlessInit] : [],
});
```

## Manifest from the browser

The `@mysten-incubation/devstack/dapp-kit` subpath also re-exports `fromManifest` and the manifest
types — the same shapes the server-side `@mysten-incubation/devstack` package uses, but importable
from a browser bundle without pulling in the Node-only factory graph. Reach for it when you have a
raw manifest JSON blob (a snapshot, an out-of-band fetch) and need to decode it:

```ts
import { fromManifest, type Manifest } from '@mysten-incubation/devstack/dapp-kit';

const m: Manifest = fromManifest(rawJson);
const aliceAddress = m.accounts.alice.address;
```

In normal app code you reach for the generated handles instead (`accounts`, `services`, `packages`,
`extras`, `captured`) — they're literal-typed and never require a decode step.

## Connecting via the dev wallet

Once `Wallet({ accounts: [...] })` is in your devstack, the dev wallet shows up as **Dev Wallet** in
dapp-kit's connect modal. It exposes one wallet with one entry per `Account(...)` Ref.

In tests, `connectAs(page, 'alice')` clicks that modal and switches the active account — see
[testing-playwright](./testing-playwright).
