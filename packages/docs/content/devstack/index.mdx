<Callout type="warn">
	**Prototype — not on npm.** Devstack is a prototype. Nothing is published to npm and there is no
	near-term plan to publish. The public API breaks freely as we iterate; pin nothing from outside
	this monorepo.
</Callout>

devstack brings up `sui-localnet` (plus optional Walrus storage nodes and Seal key servers),
publishes Move packages, runs codegen, and writes a typed manifest that your frontend consumes via
Vite.

```sh
# Inside this monorepo:
pnpm --filter <your-app> add -D @mysten-incubation/devstack@workspace:*
pnpm exec devstack up
```

## What you get

- **Fast cold start by design.** Warm cycles short-circuit through `getStatus`, so re-runs skip
  whatever's already converged. A sui-only stack cold-starts on the order of tens of seconds; a
  full sui+walrus+seal stack pays an upstream walrus-image build on the first run (multi-minute,
  one-time, cached forever after) and is dominated by container startup on subsequent cycles. Run
  it on your hardware and file the actual timings — devstack is a prototype and the README's
  numbers move every time the underlying images bump.
- **Snapshots.** `devstack snapshot save baseline` captures every stateful container as a
  `docker commit`'d image plus a copy of the host-side stack dir. `restore` re-tags the seed
  images so a fresh `devstack up` starts with all the seeded state in under 15 s. CI ships snapshots
  through GHCR via `--push <registry>`.
- **Declarative configuration.** Each app declares its services (sui, walrus, seal, codegen,
  imports, ...) as plugins, plus per-app state via a top-level `setup: [...]` list of actions.
  The reconciler walks the action graph, rebuilds only what drifted, and produces a manifest the
  UI imports as a virtual module.
- **Stacks with dynamic ports.** Named per-app environments with isolated containers and host
  state. The per-stack port allocator persists assignments to `<stackDir>/ports.json` so `main`
  and `test` stacks coexist without port-collision babysitting.
- **Container-layer state.** Chain ledger + walrus blob store live in their containers' writable
  layers; manifest, keys, ports, and setup markers live under `<stackDir>` on the host. No named
  docker volumes — `docker stop` / `docker start` preserves state, snapshots capture it via
  `docker commit`.
- **Publish + codegen built in.** Move packages publish via the in-container sui CLI (or host CLI
  on live nets). `@mysten/codegen` regenerates typed bindings whenever a package id changes.
- **MVR-driven typed bindings.** Codegen emits `@local/<kebab-name>` placeholders in the move-call
  builders; the SDK resolves them to live `packageId`s at transaction-build time via the
  `mvr.overrides` config that `localnetDappKitConfig(manifest)` wires up automatically.
  Component code is `tx.add(connectFour.joinLobby({ arguments: [...] }))` — same shape on
  testnet/mainnet, only `dapp-kit.ts` differs.
- **Live-network deploys.** The same plugin actions run against testnet/mainnet via
  `devstack deploy --network <n>` or `devstack apply --target <n>`.
- **`pnpm dev` starts everything.** With the [`frontend()` plugin](/devstack/plugins/frontend) loaded, the
  dev server (vite, next, anything) runs alongside sui localnet, walrus, seal, package publishes,
  and codegen — one combined process, one log stream.
