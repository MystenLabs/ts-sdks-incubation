Devstack composes a local Sui development stack from one TypeScript config. A stack is a list of
members such as `sui()`, `account()`, `localPackage()`, `wallet()`, `walrus()`, `seal()`,
`deepbook()`, and `action()`.

```ts title="devstack.config.ts"
import { defineDevstack, sui, account, localPackage, wallet } from '@mysten-incubation/devstack';

const publisher = account('publisher');
const alice = account('alice');

const hello = localPackage('hello', {
	sourcePath: './move/hello',
	publisher,
});

export default defineDevstack({
	members: [sui(), publisher, alice, hello, wallet({ accounts: [publisher, alice] })],
	stackName: 'hello',
});
```

The public package surface is:

- Root API: `defineDevstack`, `runStack`, built-in factories, plugin-author helpers, and public
  types.
- Build integrations: `@mysten-incubation/devstack/vite`, `/vitest`, `/playwright`, `/browser`, and
  `/runtime`.
- Authoring subpaths: `@mysten-incubation/devstack/contracts` and `/substrate`.

There is no exported `advanced` or `dapp-kit` package subpath. App code reads generated files and
the runtime manifest instead of importing private helpers.

## Core Flow

1. Put stack members in `devstack.config.ts`.
2. Run `devstack up` for an attached local supervisor, or `devstack apply` for a one-shot reconcile.
3. Generated files land under `src/generated` by default. Runtime state, manifests, snapshots, and
   logs stay under `.devstack/stacks/<stack>`.
4. Use the Vite, Vitest, Playwright, browser, or runtime subpaths from application tooling.
