title: Devstack
description: Hermetic local Sui dev stack — composed from Refs.

Devstack is a dev-time tool that boots everything a Sui dApp needs in
one process: a local validator with a faucet, your Move packages,
funded accounts, Walrus, Seal, DeepBook — whatever your stack uses —
and keeps them in sync with your code as you edit.

You describe the stack as a list of **Refs**:

```ts
// devstack.config.ts
import { devstack, Sui, Account, Package, Bindings } from '@mysten-incubation/devstack';

const alice = Account('alice', { funding: { SUI: 1_000_000_000n } });
const hello = Package('hello', './move/hello', { signer: alice });

export default devstack(
	Sui(),                                  // localnet by default
	alice,
	hello,
	Bindings({ packages: [hello], output: './src/generated' }),
);
```

Then `pnpm dev` boots the stack: a TUI shows the localnet booting,
faucet funding alice, `sui client publish` running, and `@mysten/codegen`
emitting TypeScript bindings for `hello`. Edit a `.move` file and the
whole pipeline reruns with the new packageId.

## What you get

- **A single config** — Refs compose, type-check, and double as
  `yield*`-able Effect tags. No plugin manifests, no YAML.
- **Hot restart on edits** — file watchers tear down and re-acquire
  the affected primitives. `publishMove` watches your Move sources;
  `Bindings` re-emits when the package id changes.
- **A manifest sidecar** — `.devstack/manifest.json` carries the
  resolved endpoints, package ids, and account addresses. Your
  frontend, e2e tests, and dapp-kit setup read from it.
- **Hermetic-by-default** — every container is labelled with your
  `<app, stack, network>` triple so parallel stacks coexist without
  collision. `devstack wipe` cleans yours up.
- **Effect-native** — the runtime is built on Effect v4. Use it
  directly via `yield* Sui`, or call `devstack(...).run()` and forget
  about it.
