---
title: Migrating to the Ref API
---

The Phase 2 redesign replaces the flat `defineDevstack([...])` array with
the variadic `devstack(...)` entry point and a small set of factory
functions that return **typed Refs**. Cross-references are values
(`signer: alice`), not strings, so missing dependencies are compile
errors rather than runtime surprises.

This page maps every v3 export to its v4 equivalent. Both APIs live
side-by-side during the transition; new code should reach for the v4
Ref factories under [`@mysten-incubation/devstack/services`](#imports).

## Side-by-side: the minimal template

**Before (v3):**

```ts
import {
	accounts, defineDevstack, hostProcess, manifest, publishMove,
	suiLocalnet, tx, walletApp,
} from '@mysten-incubation/devstack';

const a = accounts({ alice: {}, bob: {} });
const helloPublish = publishMove({ name: 'hello', path: HELLO_DIR, signer: a.alice });
const mintGreeting = tx({
	name: 'mint-greeting',
	signer: a.alice,
	dependsOn: [helloPublish],
	build: (t) => Effect.gen(function* () {
		const pkg = yield* helloPublish;
		t.moveCall({ target: `${pkg.packageId}::hello::mint`, ... });
	}),
});
const wallet = walletApp({ accounts: [a.alice, a.bob], allowedOrigins: ['http://localhost:5179'] });
const dev = hostProcess({ name: 'frontend.dev-server', command: 'pnpm', args: ['exec','vite'], ... });

export default defineDevstack([suiLocalnet(), a.alice, a.bob, helloPublish, mintGreeting, manifest(), wallet, dev]);
```

**After (v4):**

```ts
import { devstack } from '@mysten-incubation/devstack';
import { Account, Action, Dev, Package, Wallet } from '@mysten-incubation/devstack/services';

const alice = Account('alice');
const bob = Account('bob');

const hello = Package('hello', HELLO_DIR, { signer: alice });

const mintGreeting = Action('mint-greeting', {
	signer: alice,
	needs: [hello],
	build: (t) => Effect.gen(function* () {
		const pkg = yield* hello;
		t.moveCall({ target: `${pkg.packageId}::hello::mint`, ... });
	}),
});

const wallet = Wallet({ accounts: [alice, bob], allowedOrigins: ['http://localhost:5179'] });
const dev = Dev({ command: 'pnpm', args: ['exec', 'vite', '--port', '5179'], needs: [hello, wallet] });

export default devstack(alice, bob, hello, mintGreeting, wallet, dev);
```

Three concrete changes:

1. **`accounts({...})` → one `Account(name)` call per account.** No more
	 `a.alice, a.bob` splat into the stack array — each Account is its
	 own typed value.
2. **`publishMove`, `tx`, `hostProcess`, `walletApp` → `Package`,
	 `Action`, `Dev`, `Wallet`** with the new positional / option shapes.
3. **`defineDevstack([...])` → `devstack(...refs)`.** Variadic over Refs,
	 auto-includes `manifest()`, and auto-fills `Sui()` when missing.

## Imports

The v4 Ref factories live on the `/services` subpath; the `devstack(...)`
entry point and the `Devstack` Effect Service stay on the main barrel:

```ts
import { devstack, Devstack, fromManifest } from '@mysten-incubation/devstack';
import {
	Account, Action, Bindings, Dev, Deepbook, Package, Seal, Sui, Walrus, Wallet,
} from '@mysten-incubation/devstack/services';
```

The subpath split avoids the v3 `Sui` Context.Service tag (still on the
main barrel) colliding with the v4 `Sui()` factory function. Phase 6 of
the redesign will delete the v3 tag re-export and promote the factories
to the main barrel.

## Cross-references are typed values, not strings

The biggest day-to-day change. In v3:

```ts
const a = accounts({ alice: {} });
const hello = publishMove({ name: 'hello', signer: a.alice });
```

`a.alice` is a reference; if you typo `a.aliec` you get a compile error.
But `signer: 'alice'` (if v3 had accepted string refs) would not have
been checked.

In v4:

```ts
const alice = Account('alice');
const hello = Package('hello', path, { signer: alice });   // ✓ typed
const hello2 = Package('hello2', path, { signer: 'alice' }); // ✗ compile error
```

The Ref is the only accepted form. No string-name lookup, no runtime
"account not found" surprises. The same rule applies to `Action.needs`,
`Wallet.accounts`, `Dev.needs`, and `Bindings.packages`.

## `Effect` consumers (`provideDevstack` → `.layer`)

For Effect-native consumers (scripts, agents, the `effect-app` example):

**Before (v3):**

```ts
const a = accounts({ alice: {} });
const layer = provideDevstack([suiLocalnet(), a.alice]);
runMain(program.pipe(Effect.provide(layer)));
```

**After (v4):**

```ts
const alice = Account('alice');
const stack = devstack(Sui(), alice, { disableManifest: true });
runMain(program.pipe(Effect.provide(stack.layer)));
```

The `program` body stays the same: `yield* Sui`, `yield* alice` both
work. The `Devstack` Effect Service is also available as a one-import
alternative — `const { services, packages, accounts } = yield* Devstack`.

## Reading the manifest

The on-disk manifest schema is now v4 — records keyed by name, sectioned
by user intent. Existing v3 manifests on disk are migrated to v4 in
memory by `fromManifest()`. `localnetMvrOverrides` and
`localnetDappKitConfig` from `@mysten-incubation/devstack/dapp-kit` work
unchanged against both shapes.

For non-Effect TS code that wants a typed read:

```ts
import { fromManifest, type Manifest } from '@mysten-incubation/devstack';
const ds: Manifest = fromManifest(await fetch('/devstack.json').then((r) => r.json()));
ds.services.sui?.rpc.url;
ds.packages.hello?.id;
ds.accounts.alice?.address;
```

## What's deferred

A few v3 conveniences haven't moved to the Ref API yet — they continue
to live on the main barrel:

- `bindings({...})` — `Bindings({...})` exists but is still always
	explicit; the Phase-6 step adds an auto-pull when any `Package` is
	declared.
- `manifest({extras})` — `devstack(...)` calls the v3 `manifest()` under
	the hood. Pass `extras` via the (forthcoming) `expose:` field on
	individual `Action` refs; until then continue using the v3 `manifest()`
	factory for custom extras.
- Apply-time invariant validation (e.g. `ephemeral-funded` accounts
	rejected on `Sui({ network: 'testnet' })`) — currently surfaces as a
	runtime error rather than a compile-time / apply-time check.
