---
title: Manifests
description: The per-stack JSON the runtime emits and the frontend consumes.
---

After every successful reconcile, devstack writes a manifest to disk:

- **Localnet:** `<appDir>/.devstack/stacks/<stack>/manifest.json`.
- **Live networks:** `<appDir>/.devstack/manifests/<network>.json`.

The manifest captures the registry: every package id, account address, service URL, and
plugin-namespaced entry. The frontend reads it via the `virtual:devstack-manifest` Vite virtual
module — see the [Vite adapter](/docs/adapters/vite).

See the [Manifest format](/docs/manifest) reference for the full schema.

## Why per-stack on localnet

Multiple localnet stacks coexist on disk. `pnpm exec devstack stack use scratch` flips the active
pointer; the next `up`/`apply` writes to that stack's manifest. The Vite dev server watches the
active pointer and reloads the virtual module on switch.

## Why per-network on live nets

`testnet` is a single shared chain — there's only one for a given app. Stacks are a localnet-only
convention (multiple isolated chains on one host); on live nets the manifest is keyed by network
name only.
