title: CLI reference
description: Every devstack subcommand.
---

```text
devstack <command> [options]

Commands:
  up [config]                  Long-running supervisor: brings the stack up + watches sources.
  apply [config] [--target]    Single-cycle reconcile against active stack or --target.
  deploy <config> --network    Live-network deploy slice (skip Service; keep Build).
  codegen [config] [--target]  Re-emit codegen against the prior manifest (read-only).
  down [config]                Stop the active stack's containers (writable layer preserved).
  reset [config] --yes         Wipe the active stack — containers + host state.
  stack list|new|use|down|drop Manage named per-app stacks.
  snapshot save|restore|list|rm|hash
                               Capture / restore named snapshots of a stack.
  console [config] [--target]  REPL with manifest, client, accounts pre-bound.
```

## up

```
devstack up [config] [--target <network|stack|network:stack>] [--stack <name>]
```

Long-running supervisor that brings the stack up and watches Move sources. Defaults to
`./devstack.config.ts` and the active stack from `<appDir>/.devstack/active`. The supervisor is
localnet-only; live-network targets error with a hint pointing at `apply` or `deploy`. Use
`devstack apply` for the equivalent single-cycle CLI.

## apply

```
devstack apply [config] [--target <network|stack|network:stack>] [--actions a,b,c]
```

Single-cycle reconcile via `runOneShot`. Runs every action kind on localnet (Service+Build
included); on live networks (testnet/mainnet) skips Service+Build and runs
Publish/Register/Seed/Emit. Use `--actions` (alias `--scope`) to restrict the cycle to a
comma-separated set of action FQNs (e.g. `wallet.usdc,imports.deepbook`); the runtime walks `needs`
transitively to keep dependencies in the cycle and auto-includes every Emit action so the codegen
cascade still fires.

## deploy

```
devstack deploy <config> --network <testnet|mainnet>
```

Reads `config.networks[network]` for `rpcUrl`. Filters Service actions; keeps Build (so the Move
build still happens via the host sui CLI). Useful for live deploys from CI. Pre-C1 default behavior
is preserved; new code should prefer `apply --target <network>`.

## codegen

```
devstack codegen [config] [--target <network|stack|network:stack>]
```

Re-emit typed bindings against the prior manifest, without running any other action. `readOnly` —
does not write the manifest back. Useful when you've changed `@mysten/codegen` config or pulled new
bindings without a fresh deploy.

## down

```
devstack down [config]
```

Stops the active stack's containers; the writable layer persists (resumable on next `up`).
Shortcut for `devstack stack down`.

## reset

```
devstack reset [config] --yes
```

Wipes the active stack — containers + host state under `.devstack/stacks/<active>/`. Requires
`--yes` (refuses without). Shortcut for `devstack stack drop --force --yes` against the active
stack.

## stack

```
devstack stack list|new <name>|use <name>|down [<name>]|drop <name> --yes [--force]
```

Manage named per-app stacks. Each stack maps to an isolated set of containers (state in their
writable layers) and a host-side dir at `.devstack/stacks/<name>/` (manifest, keys, ports.json,
setup markers). `drop` refuses the active stack and `main` unless `--force` is passed; the
`reset` shortcut auto-passes `--force`.

## snapshot

```
devstack snapshot save <alias> [--stack <name>] [--push <registry>]
devstack snapshot restore <alias|id> [--stack <name>] [--force-arch]
devstack snapshot list [--stack <name>]
devstack snapshot rm <alias|id>
devstack snapshot hash [--stack <name>]
```

Capture / restore named snapshots of a stack.

`save` quiesces every container labeled for the stack (`docker pause` for sui's RocksDB,
`docker stop` for batched-write services like walrus storage nodes), `docker commit`s each
seeded container into a content-addressed image (e.g.
`devstack-snapshot/<sha>/token-studio-main-sui:seeded`), and copies `<stackDir>` into
`<appDir>/.devstack/snapshots/<sha>/`. With `--push <registry>`, also tags + pushes the seed
images so other machines / CI runners can pull them on `restore`.

`restore` re-tags each seed image back to its original tag — so the plugin's next `docker run`
from its hardcoded image picks up the seeded layer — and restores `<stackDir>` from the bundle.
The next `devstack up` short-circuits via `getStatus` because every action's state is already in
place. Refuses cross-arch restore by default; use `--force-arch` to override (RocksDB binary
format may corrupt across darwin/arm64 ↔ linux/amd64).

`hash` prints the content-addressed `<sha-id>` for the current config without doing anything
else — useful as a CI cache key.

## console

```
devstack console [config] [--target <network|stack|network:stack>]
```

REPL with `manifest`, `client`, `accounts.<name>`, `packages.<name>.<fn>()` pre-bound. Reads the
active-stack manifest (or the `--target`'s manifest) and dynamically imports codegen-generated
bindings.

REPL commands:

- `.deploy [pkg]` — Run `apply` against the resolved target. Without args, runs every action; with
  `<pkg>`, scopes to that action's FQN + transitive deps + the codegen Emit cascade. `<pkg>` may be
  a bare action name (the runtime resolves it against the loaded plugins), a dotted FQN
  (`arena.connect_four`), or `imports/<name>`.
