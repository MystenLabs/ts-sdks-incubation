Subpath: `@mysten-incubation/devstack/react`. The surface is intentionally minimal: a manifest
provider, a deployment-readiness gate, and config-input helpers that get spread into vanilla
`createDAppKit({...})` and `new WalrusClient({...})`. App TSX uses no devstack-specific signing
hooks or codegen wrappers — those are generic SDK ergonomics that live in dapp-kit-react /
codegen / a small per-app `lib/queries.ts` helper. Production app code looks identical; only
`dapp-kit.ts` differs (drops the `localnetDappKitConfig` spread).

```sh
pnpm add @mysten/dapp-kit-react @mysten/dapp-kit-core @mysten/sui @tanstack/react-query react react-dom
pnpm add @mysten-incubation/dev-wallet @mysten-incubation/devstack-wallet-panels
```

## Setup

```tsx
// dapp-kit.ts
import { createDAppKit } from '@mysten/dapp-kit-core';
import { devWalletInitializer } from '@mysten-incubation/dev-wallet';
import { createDevstackAdapterFromManifest } from '@mysten-incubation/dev-wallet/adapters';
import { localnetDappKitConfig } from '@mysten-incubation/devstack/react';
import { configureDevstackPanels, devstackPanels } from '@mysten-incubation/devstack-wallet-panels';
import { manifest } from 'virtual:devstack-manifest';

configureDevstackPanels(manifest);

const devstackAdapter = createDevstackAdapterFromManifest(manifest);

export const dAppKit = createDAppKit({
	...localnetDappKitConfig(manifest),
	walletInitializers: [
		devWalletInitializer({
			adapters: devstackAdapter ? [devstackAdapter] : [],
			panels: devstackPanels(),
			autoConnect: true,
			autoApprove: true,
			mountUI: true,
		}),
	],
});

declare module '@mysten/dapp-kit-react' {
	interface Register {
		dAppKit: typeof dAppKit;
	}
}
```

`localnetDappKitConfig(manifest)` returns the `defaultNetwork` / `networks` / `createClient`
triple. The `createClient` factory builds a `SuiGrpcClient` whose `mvr.overrides.packages` is
pre-loaded from the manifest so codegen-emitted `@local/<kebab-name>` placeholders resolve to
live `packageId`s at transaction build time. App code calls `tx.add(connectFour.joinLobby({ arguments: [...] }))`
directly — no per-call binding required.

`createDevstackAdapterFromManifest` reads the `wallet-server` entry from
`manifest.registry.services` and returns a configured
[`DevstackSignerAdapter`](/dev-wallet/guides/devstack-integration), or `null` when the manifest is
empty (no `localnet:up` yet). Pair this with the [`walletServer()`](/devstack/plugins/wallet-server)
plugin so the adapter has a server to talk to. Private keys never enter the frontend bundle —
signing happens HTTP-side in the supervisor process.

```tsx
// main.tsx
import { DevstackProvider } from '@mysten-incubation/devstack/react';
import { DAppKitProvider } from '@mysten/dapp-kit-react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { manifest } from 'virtual:devstack-manifest';
import { dAppKit } from './dapp-kit';

const queryClient = new QueryClient();

createRoot(document.getElementById('root')!).render(
	<QueryClientProvider client={queryClient}>
		<DAppKitProvider dAppKit={dAppKit}>
			<DevstackProvider manifest={manifest}>
				<App />
			</DevstackProvider>
		</QueryClientProvider>
	</QueryClientProvider>,
);
```

## Component-level transaction flow

Apps call codegen builders directly and submit via the wallet's `signAndExecuteTransaction`.
The MVR substitution happens transparently at tx-build time.

```tsx
import { Transaction } from '@mysten/sui/transactions';
import * as connectFour from './generated/sui/connect_four/game';
import { useSignAndExecute } from './lib/queries';

function LobbyView({ lobbyId }: { lobbyId: string }) {
	const { mutateAsync, isPending } = useSignAndExecute({ invalidateKeys: [['arena']] });

	async function onJoin() {
		const tx = new Transaction();
		tx.add(connectFour.joinLobby({ arguments: [lobbyId] }));
		await mutateAsync(tx);
	}

	return (
		<button onClick={onJoin} disabled={isPending}>
			Join
		</button>
	);
}
```

`useSignAndExecute` is an app-local helper (~50 lines) that wraps `dAppKit.signAndExecuteTransaction`
with `useMutation` ergonomics, a post-tx `waitForTransaction` step, and react-query invalidation.
Each example app carries its own copy in `src/lib/queries.ts`. Reproducing it once per app keeps
production code structurally identical to localnet code; the helper has no devstack-specific
logic.

## useDevstackManifest()

Returns the active manifest (the `Manifest` shape published by
[`virtual:devstack-manifest`](/devstack/adapters/vite)). Throws when no manifest is loaded —
typically because `localnet:up` hasn't run yet.

```tsx
import { useDevstackManifest } from '@mysten-incubation/devstack/react';

const manifest = useDevstackManifest();
const rpcUrl = manifest.registry.services.find((s) => s.name === 'sui-rpc')?.url;
```

Most apps go through `useDevstackDeployed` for the readiness gate and read the manifest only when
they need a specific service URL or shared-object reference.

## useDevstackDeployed(options?)

Returns true when the manifest is loaded AND has at least one registered account AND every package
in `options.requirePackages` (if set) is present. Replaces the per-app `isDeployed` constants.

```tsx
import { useDevstackDeployed } from '@mysten-incubation/devstack/react';

function App() {
	const deployed = useDevstackDeployed({ requirePackages: ['connect_four'] });
	return deployed ? <DeployedView /> : <NotDeployedView />;
}
```

Without `requirePackages`, returns true as long as the manifest has any account and any package — a
coarse "stack is up at all" check.

## localnetDappKitConfig(manifest, opts?)

Returns the dapp-kit config inputs for the localnet network: `defaultNetwork: 'localnet'`,
`networks: ['localnet']`, a `createClient` factory that builds a `SuiGrpcClient` pointed at the
manifest's `sui-rpc` URL with MVR overrides pre-wired, and `enableBurnerWallet: true`.

| Option               | Notes                                                                          |
| -------------------- | ------------------------------------------------------------------------------ |
| `localnetRpcUrl`     | Override the manifest-derived URL (e.g. when proxying through a tunnel).       |
| `additionalNetworks` | Extra networks beyond `'localnet'`.                                            |
| `networks`           | Per-network RPC URL map for any `additionalNetworks` declared.                 |
| `enableBurnerWallet` | Default `true`.                                                                |
| `mvrName`            | Override the placeholder mapper. Default kebab-cases + prefixes `@local/`. Pair with the same option on `codegen({...})`. |

## localnetMvrOverrides(manifest, opts?)

Returns `{ packages: Record<string, string> }` mapping `@local/<kebab-name>` placeholders to live
`packageId`s. Spread into `SuiGrpcClient`'s `mvr.overrides`. `localnetDappKitConfig` does this
automatically — call this directly only when you're constructing a SuiClient outside of dapp-kit.

```ts
import { SuiGrpcClient } from '@mysten/sui/grpc';
import { localnetMvrOverrides } from '@mysten-incubation/devstack/react';

const client = new SuiGrpcClient({
	network: 'localnet',
	baseUrl: 'http://127.0.0.1:9000',
	mvr: { overrides: localnetMvrOverrides(manifest) },
});
```

## localnetWalrusOptions(manifest, init?)

Returns `{ packageConfig, storageNodeClientOptions: { fetch } }` for `new WalrusClient({...})`.
The fetch override translates docker-internal storage-node URLs (`https://10.0.0.10–13:9185`) to
the host-mapped plain-HTTP equivalents the browser can reach.

```ts
import { WalrusClient } from '@mysten/walrus';
import { localnetWalrusOptions } from '@mysten-incubation/devstack/react';

const client = new WalrusClient({
	suiClient,
	...localnetWalrusOptions(manifest),
	wasmUrl,
});
```

On testnet/mainnet drop the spread; same call shape, different config inputs.

## defaultMvrName(name)

The default placeholder mapper: `(n) => '@local/' + n.replace(/_/g, '-')`. Mirrors the codegen
plugin's default. Apps with a custom MVR org configure `codegen({ mvrName })` AND
`localnetDappKitConfig(manifest, { mvrName })` with the same function.
