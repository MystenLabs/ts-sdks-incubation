---
title: Lifecycle
description: How the current runtime boots and stops a stack.
---

`defineDevstack(...)` is synchronous. It builds a static stack handle and performs composition-time
checks. The runtime path starts when a surface consumes that handle.

Runtime surfaces:

- `devstack up` starts a supervisor and stays attached.
- `devstack apply` starts the same supervisor path in one-shot mode.
- `runStack(stack, opts)` embeds the supervisor in another TypeScript program.

```ts
import { Effect } from 'effect';
import { account, defineDevstack, runStack } from '@mysten-incubation/devstack';

const stack = defineDevstack(account('alice'), { stackName: 'embedded' });
const handle = runStack(stack, {
	runtimeRoot: '.devstack',
	identity: { app: 'demo', stack: 'embedded' },
});

await Effect.runPromise(handle.start);
await Effect.runPromise(handle.stop);
await Effect.runPromise(handle.awaitShutdown);
```

Boot order is derived from `consumes` edges. Members that need Sui can cause `defineDevstack` to
auto-mount a default `sui()` when none is provided. `wallet({ accounts: 'all' })` is expanded after
the full member list is known, so it consumes every account member in the final stack.

The supervisor publishes typed events, maintains a live projection, writes the manifest, emits
generated files, and serves command-channel requests from peer CLI commands. Shutdown requests flow
through the same command channel and then run scope finalizers.
