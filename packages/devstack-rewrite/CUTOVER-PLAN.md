## Step 1 — Verify gates

Block cutover until all of the following are green:

- [ ] `pnpm --filter @mysten-incubation/devstack-rewrite typecheck` passes.
- [ ] `pnpm --filter @mysten-incubation/devstack-rewrite vitest run` passes (all `test/` suites,
      including `test/e2e/*-boot.test.ts`).
- [ ] Every `examples/*-rewrite/` package typechecks against the rewrite.
- [ ] Every paired rewrite example boots via its `devstack.config.ts` (covered by the per-example
      `*-boot.test.ts` files under `packages/devstack-rewrite/test/e2e/`).
- [ ] The 3 CI matrix examples in `devstack-e2e.yml` — `arena`, `private-content`, `deepbook-full` —
      each have working `-rewrite/` counterparts whose playwright e2e tests pass against the rewrite
      stack. (Confirm by running the suites locally on the user's machine, not via CI.)
- [ ] CLI parity: the rewrite ships a `devstack` bin equivalent to the old package's
      `dist/cli/main.mjs` (currently absent — see Risks). At minimum `apply`, `up`, `snapshot save`,
      `snapshot restore` must work, since `devstack-e2e.yml` invokes them.
- [ ] No `*-rewrite/` example has lingering imports from `@mysten-incubation/devstack` (old). Grep
      clean.
- [ ] Decide whether originals (`examples/_template/`, `examples/arena/`, …) are deleted or kept as
      a v3 reference. Recommend delete (per "no pre-existing excuses" / "no compat for never-cases")
      since devstack is unreleased.

## Risks

1. **CLI gap is load-bearing for CI.** The rewrite has no `bin: devstack`, no built CLI, no `dist/`.
   The CI workflow `devstack-e2e.yml` invokes `node ../../packages/devstack/dist/cli/main.mjs ...`
   directly. The cutover cannot ship until either (a) the rewrite implements equivalent CLI verbs
   (`apply`, `up`, `snapshot save`, `snapshot restore` minimum) and builds them, or (b)
   `devstack-e2e.yml` is rewritten to a different driver. The rewrite's
   `notes/redesign/architecture.md` and `v2-requirements/20-cli.md` describe what CLI parity looks
   like, but implementation isn't here yet.

2. **Subpath-export shape mismatch.** Old: `./vitest`, `./playwright`, `./vite`, `./browser`,
   `./advanced`. New: `./build-integrations/vitest`, `./build-integrations/playwright`,
   `./plugins/sui`, etc. Rewrite examples already use the nested form — keeping that shape forces
   every doc snippet in `packages/docs/content/devstack/**/*.mdx` to be rewritten. Either reshape
   the new exports to match the old (cheaper for docs/migrators) or accept doc churn (cheaper inside
   the rewrite). Pick before cutover.

3. **`create-devstack-app/template/` regeneration.** This template is a snapshot of
   `examples/_template/`. After the rename it must be re-snapshotted from `examples/_template/`
   (post-rename) and republished. The template's dependency on `@mysten-incubation/devstack@^0.0.0`
   will resolve in npm-land once the renamed package publishes — but the v3 published package (if
   any exists on npm) will not match the rewrite's API. This is fine because the README says
   devstack isn't published.

4. **Stale runtime artifacts on disk.** Long-running examples have `.devstack/stacks/`,
   `.devstack/manifest.json`, etc. on disk. Snapshots captured against v3 won't restore into the
   rewrite's runtime layout. Plan to nuke `examples/*/.devstack/` directories at cutover. Already
   gitignored (so no commit churn), but should be documented in cutover release notes so
   contributors don't get cryptic restore failures.

5. **Inconsistent example naming.** Pre-cutover names mix `@mysten-incubation/<name>` (originals:
   `arena`, `wallet`, …), `@mysten-incubation/example-<name>-rewrite` (most rewrites), and
   `@mysten-incubation/<name>-rewrite` (`_template-rewrite`, `plugin-author-redis-rewrite`). The
   rename is the one chance to standardise. Pick a convention (recommend
   `@mysten-incubation/example-<name>` for everything under `examples/`, with `_template` and
   `plugin-author-redis` as is).

6. **`hello-world`, `deepbook-mini`, `postgres-mini`, `seal-mini`, `walrus-mini`** are net-new
   examples in the rewrite. They have no original counterpart, so the rename is a simple
   `git mv <name>-rewrite/ <name>/`. No blocker.

7. **Lockfile churn.** A single `pnpm install` after Step 4 regenerates `pnpm-lock.yaml` with all
   renames. Expect a large diff. Best done as a dedicated commit at the tail end of the cutover PR.

8. **One CI workflow at risk: `devstack-e2e.yml`.** `pkg-pr-new.yml`, `turborepo.yml`,
   `changesets*.yml`, `validate-ai-assistance.yml` are all per-package-name-agnostic and survive the
   rename.

## Estimated effort

Excluding the unimplemented CLI (which is a feature, not a rename), the cutover itself is ~half a
day of mechanical work plus another half-day of verification:

- Step 1 (gates): blocked on rewrite feature completeness, not on this work.
- Step 2 (delete old): ~5 min, `git rm`.
- Step 3 (notes migration): ~15 min, `git mv` + `README.md` link updates.
- Step 4 (rename + self-ref sweep): ~30 min, mostly the `build-integrations/vitest/config.ts`
  setup-file specifier.
- Step 5a-c (examples + create-devstack-app template): ~1 hour. Bulk package.json edits +
  `create-devstack-app/scripts/sync-template.ts` re-run.
- Step 5d (CI rewrite): **separate effort, not part of this rename.** Blocks the rename from landing
  on `main` but isn't billed to the cutover commit.
- Step 5e (peripheral consumers): ~30 min.
- Step 6 (verification): ~1-2 hours including a local devstack-e2e run.

The dominant cost is the CLI gap (Risk 1). The actual rename is small.

---

## Recommended cutover sequence

1. Bring the rewrite to CLI parity (separate PRs, not part of cutover).
2. Rewrite `.github/workflows/devstack-e2e.yml` against the rewrite's test shape (separate PR, while
   old package still exists, so CI stays green).
3. Land a single cutover PR: Steps 2-6 above in one commit (or one tight series). Don't split the
   rename across multiple commits — workspace is broken between commits if you do.
4. Once green on `main`, follow up with example-naming normalisation (Risk 5) as a smaller PR.
